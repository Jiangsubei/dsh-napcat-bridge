## 0. 背景与目标

dsh-napcat-bridge 作为 DeepSeek Harness × NapCat QQ 桥接插件，当前具备消息收发、Agent工具、记忆回顾、设置卡等能力。本批需求新增：
- 消息表情回应（贴表情）工具
- 好友管理 / 群管理工具（含工具权限开关）
- 加好友请求专用独立 Session（阅后即焚 + 决策策略）
- 后台审计日志
- Web UI 设置卡从单列平铺重构为 Tab 分区分组

**总体设计哲学（贯穿本批全部需求）**：
> 能力门控 = 开关控制工具注册/可见性（破坏性/高触点能力，默认关闭）
> 使用引导 = 行为准则（低风险能力，常驻、Agent 自决）
> 赋能但不替 Agent 做决定：应用层不做决策兜底，只忠实记录决策日志

## 1. 会话类型 / 工具可见性矩阵（总纲）

| 会话类型 | 群管理工具 | 好友管理工具 | 贴表情工具 |
|---|---|---|---|
| 普通群聊 Session | ✅（直接在该群 Session 内调用） | ❌ | ✅（仅群聊） |
| 普通私聊 Session | ❌ | ❌ | ❌（私聊无贴表情功能） |
| 加好友专用 Session | ❌ | ✅（仅此 Session 有） | ❌ |

**结论**：
- 群管理工具**跟着群走**（在对应群的普通 Session 里调用，不独立）。
- 好友管理工具**只出现在加好友专用 Session**；普通私聊/群聊 Session 均不注册。
- 贴表情工具**仅群聊注册**（私聊不生效，需在工具注册层按 Session 类型区分）。

## 2. 需求 A：贴表情（Reaction）工具

### 2.1 定位与形态
- **仅做 Agent 工具**（放弃程序层随机贴——与 Agent 工具重复会显得怪异）。
- 工具描述（忠实）**："收到消息时可调用本工具，以表情回应。"**
- **仅群聊注册**：Session 为私聊时，工具不注册、不可见；群聊才注册。
- 在 Agent 回复文本**之前**调用。

### 2.2 工具签名（初稿）
```
react_message { message_id?, emoji: enum[...] }
```
- `message_id`：可省略，默认 = 当前回合正在回复的那条入站消息。
- `emoji`：**语义键枚举**（如 thumbs_up / heart / laugh / cry / surprise / ok …），内部映射为 QQ 的 `emoji_id`。

### 2.3 表情参考集
- **开工前必须先做调研/探针**确认一组**实测可用**的常见表情 `emoji_id` 并固化（QQ 表情回应用数值 id，无公开稳定文档）。
- 参考集确定后，做「语义键 → emoji_id」映射表进工具实现。

### 2.4 配置
- **无设置卡开关**（常驻，仅群聊注册）。
- 是否使用由 Agent 依**行为准则**自决（用户可在 behavior 里配置）。

### 2.5 边界
- 群聊可用；私聊不生效（不注册，天然规避）。

## 3. 需求 B：好友管理与群管理工具（含工具权限开关）// 配置的粒度最好是可以按群配置，每个群配置是否开启，白名单制

### 3.1 工具列表（Action 依据 NapCat/OneBot11，均已有成熟 action）

**好友管理工具**（仅在加好友专用 Session 注册）：

| 工具 | 对应 Action |
|---|---|
| 好友列表查询 | `get_friend_list` / `get_friends_with_category` |
| 同意/拒绝好友请求 | `set_friend_add_request`（flag, approve, remark） |
| 删除好友 | `delete_friend`（go-cqhttp 扩展） |
| 查询陌生人信息 | `get_stranger_info` |

**群管理工具**（在对应群的普通 Session 注册）：
| 工具 | 对应 Action |
|---|---|
| 禁言/解除禁言 | `set_group_ban`（duration，0=解除） |
| 全员禁言 | `set_group_whole_ban` |
| 踢人 | `set_group_kick`（reject_add_request） |
| 同意/拒绝加群请求或邀请 | `set_group_add_request`（flag, approve, reason） |
| 群成员列表 | `get_group_member_list` |
| 禁言列表 | `get_group_shut_list` |

### 3.2 工具权限配置（批注：群管理按群白名单制）
**好友管理工具**（全局，仅在加好友专用 Session 注册）：
- 全局总开关 + 细分开关：`friend_management_enabled` → 细分：好友列表 / 好友请求 / 删好友（每项一个布尔）。
- 默认关；关=工具不注册。

**群管理工具**（**按群白名单制配置**）：
- **每个群单独配置是否开启群管理工具**（白名单制：仅显式加入白名单的群，其 Session 才注册群管理工具）。
- 每个群的配置再细分到工具层级。
- 结构示意：
  ```
  group_management: {
    "<群号A>": { enabled: true,  tools: { ban: true, kick: true, add_request: true, member_list: false } },
    "<群号B>": { enabled: false }
  }
  ```
- 白名单外 / 未配置的群：不注册任何群管理工具。

**共性**：
- **开关 = 工具注册/可见性**：关闭则该工具**不注册**，Agent 看不到、无能力；开启才注册可见。
- **不做运行时审批**：能力纯靠"开关前置门控"。理由：独立 Session 无可审批人 + 插件可能无人看守。
- 默认全部关闭（闭合默认，安全）。

## 4. 需求 C：加好友请求专用独立 Session // 这个 session 只提供必要且关联的工具，类似后台回顾

### 4.1 会话模型
- 好友请求（`request` 事件，`request_type='friend'`，字段 `user_id / comment / flag`）**不归属任何已有 QQ 会话**，走**独立专用 Session**。
- 采用**单一收件箱**形态（peer 形如 `friend_requests`），请求队列逐条处理。
- **阅后即焚**：处理完删除该临时 Session（同 Background Review 设计），不留痕。

### 4.2 会话工具白名单（批注：仅提供必要且关联的工具，同后台回顾）
- 加好友专用 Session **只注册处理好友请求所必需的工具**，形成受限工具沙箱（类似 Background Review 的 `ALLOWED_MEMORY_REVIEW_TOOLS` 白名单）：
  - 好友管理工具（`get_friend_list` / `set_friend_add_request` / `delete_friend` / `get_stranger_info`）
  - 记忆读取工具（`read_memory`，按需读请求者画像）
- **不注册**通用工具（bash / send_file / 审批 / 群管理 等），防止无人看守的该 Session 获得全量 Agent 能力。

### 4.3 决策上下文注入
处理好友请求时，向该 Session 注入：
1. **请求者跨场景 User Profile**（若有）：`user_<qq>.md`（User Profile 本身跨群/私聊互通，是稳定锚点）。
2. **`friend_request_policy` 决策准则**（见 4.4）。

### 4.4 加好友决策准则（可配置）
- Web UI 增加 `friend_request_policy` **多行输入框**（类 persona/behavior）。
- **默认兜底策略**（内置，用户在输入框覆盖/补充）：
  1. **User Profile 中没有的，原则上不加**；但请求理由合理（comment 合理）可加。
  2. **不要因 User Profile 中曾与用户有冲突就不加**；除非画像中**明确标记此人不可信**。
- **不可信必须显式标记**（普通不愉快不等于不可信，需画像明确"不可信"才拒）。
- **应用层不做决策兜底**：是否同意/拒绝由 Agent 依策略+画像判断；应用层不替 Agent 决定（赋能不代决），只忠实记录日志。
- **暂不做同意时填备注**（另一层复杂度，后续再说；QQ 号是稳定锚点，后续可基于画像补）。

### 4.5 决策行动
- Agent 调 `set_friend_add_request(flag, approve)`（本 Session 持有的好友管理工具）完成同意/拒绝。

## 5. 需求 D：后台审计日志

### 5.1 需求
两个独立 Session 都需**后台可审计**：
- Background Review（既有）
- 加好友专用 Session（本批新增）

审计内容：**Agent 干了什么、做了什么决策**。

### 5.2 存储
- 存放于 `napcat` 顶层目录下（与 `napcat_memory` 同级，如 `napcat/audit/`）。
- **阅后即焚 ≠ 失审计**：决策日志必须**先写入持久审计目录，再销毁临时 Session**——Session 消灭但决策记录存活。

### 5.3 待细化
- 日志**具体格式 / 记录字段**：待细化（本批需求文档先记需求，格式另行定稿）。
- 是否需要审计日志开关：待定（倾向有，`audit_log_enabled`，默认？）。

## 6. 需求 E：Web UI 设置卡 Tab 重构 // 补充每页的设计 ascii 图

### 6.1 现状问题
设置卡当前**单列平铺约 27 项**，无分组、无分区；随本批新增（好友/群管理开关、friend_request_policy、审计配置）进一步膨胀，需重构。

### 6.2 组件约束（重要）
- **复用 DeepSeek Harness Web UI 现有组件**（ValueField / SwitchField / 现有表单控件），**不自行设计新组件**；本次仅改**布局**（分组/Tab 结构），不改组件风格。

### 6.3 结构：单卡 + Tab 分区（定稿）
卡片展开后顶部一排 Tab，点击切换分区；底部一个**全局"保存全部"**，跨 Tab 一次性落盘（settingsScope 一次 mutate）。

**6 个 Tab**：
| Tab | 包含项 |
|---|---|
| 连接身份 | ws_port, ws_token, bot_qq, admins, aliases, image_ttl_days |
| 回复行为 | quote_original, at_questioner |
| 人格与准则 | persona, behavior, **friend_request_policy**（多行） |
| 主动回复 | proactive_reply_enabled, only_text, random_enabled, random_probability, idle_enabled, idle_timeout, cooldown, night_dnd |
| 记忆与回顾 | memory_storage_dir, memory_budget_chars, review_enabled, review_turns_interval, review_tool_calls_interval, review_model, **审计日志配置（audit_log_enabled / audit_log_dir）** |
| 工具权限 | 好友管理（全局总开关+细分）、群管理（**按群白名单**：每群开关+细分） |

### 6.4 工具权限 Tab 交互
- **好友管理**（全局）：一个总开关，开启后展开细分复选框（好友列表/好友请求/删好友）。
- **群管理**（按群白名单）：一个"新增群"入口，列出已加入白名单的群，每个群一条（该群开关 + 细分工具复选框）；白名单外的群不显示、不注册群管理工具。
- 细分项以 3.1 / 3.2 为准。

## 7. 设计约束（全批通用）

1. 复用 DSH Web UI 组件，仅改布局；不自行设计新 UI 组件。
2. 能力门控 = 开关控制工具注册；使用引导 = 行为准则。
3. 应用层不替 Agent 做决策，只忠实记录（赋能不代决）。
4. 破坏性工具（禁言/踢人/删好友）默认关闭；闭合默认。
5. 阅后即焚会话的审计日志先持久落盘再销毁 Session。
6. 不引入新 npm 依赖（沿用现有运行环境与 DSH 扩展机制）。

## 9. 配套产出（依赖/前置）

- 工具注册层需支持**按 Session 类型**（群聊/私聊/专用Session）与**配置开关**动态注册工具（复用/扩展 `tools.guard` 隔离层）。
- NapCat 反向 WS 需能正确处理 `request` 事件（好友/加群）并透传 `flag` 等字段。
