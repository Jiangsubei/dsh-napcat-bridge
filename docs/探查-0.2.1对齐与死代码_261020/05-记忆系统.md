## 5. 结论摘要（按优先级）

1. **P1｜回顾工具白名单是假的（A1）**：`meta.allowedTools` 不在 DSH `CreateAgentOptions.meta` 白名单内、全仓无消费方；叠加 `src/index.ts:388` 对 `review-` 会话的显式放行，后台回顾子代理实际拥有全部 NapCat 工具（`send_file`、`poke_user` 等），应优先改为 `tools.restrict()`。
2. **P1｜取消/限次按不存在的 API 编写（A2）**：真实 Agent 只有 `cancel(cause)`（且未传 cause），`abortController` 无人监听，`maxIterations`/`REVIEW_MAX_ITERATIONS` 完全空转；“抢占取消”能力目前不可信。
3. **P1｜0.2.x 清理服务名写错（A3）**：`sessionProjectionCache` 应为 `sessionProjections`，`spillStore` 在 0.2.x 不存在；因被 `as any` 掩盖，typecheck 全绿也发现不了（B11）。
4. **P1｜配置旧键未收敛且迁移会把它写回（A4）**：`memory_budget_chars` 仍在 6 个文件、41 处出现，`migrate.ts:165` 整字典写回使其永久存活；交付报告“彻底剔除”不成立。
5. **P1｜`.volatile()` 一处都没有（A5）**：与交付报告“所有字段链式追加 .volatile()”直接矛盾，0.2.1 设置迁移后可能把易失值写进 profile。
6. **P1｜预算不是硬上限（B1/B2）**：私聊 session 记忆不截断、群聊“先 push 再判”，单块可大幅溢出；群聊里 default.md 还会按用户重复注入（B4），进一步挤占预算。
7. **P1｜私聊会话记忆按群聊 2200 预算写入（B3）**：与 schema 对私聊 1500 的描述冲突，且装配测试只用旧 `budgetChars`，测不出来（B17）。
8. **P1｜“当前发言人提拔”生产不可达（B10/C18）**：`ToolExecutionInput`/`Agent` 无 `userId`，测试靠伪造字段（`memory-assembly.test.ts:386`）才通过——属典型“单测自证、装配不通”。
9. **P1｜测试保护了错误契约（B16）**：`memory-review` 全 mock 且断言 `meta.allowedTools`/`meta.isBackgroundReview`/`{abort}`，正是 A1/A2 长期存活的保护伞；修复时须同步改测试（**改测试前需用户批准**）。
10. **P2｜死代码体量可观（C1-C19）**：19 项零引用/不可达/重复实现，含 2 个孤儿类型、4 个测试专用写读方法、多个只写不读字段与无人接收事件；建议随 A/B 修复一并清理，并在 `package.json` 升级 devDeps 后复跑 typecheck（A7）作为验收前提。
