## 4. 待确认项（无法在本仓库确证）

1. **0.2.1 与 0.2.0-rc.2 的类型差异**：本报告的会话快照、`settings.section` owner props、图标命名均取 0.2.0-rc.2；0.2.1 是否恢复 `SessionListState.current`、是否调整 `SettingsSectionOwnerProps`、是否新增 locale 强校验，需在安装 0.2.1 后复核（待确认）。
2. **未声明命名空间的 `locale:` 在 0.2.1 是否阻断加载**：rc.2 运行时未做命名空间存在性校验，只有渲染器要求已安装 locale face；0.2.1 的 manifest/资源扫描是否要求 `<subpath>/locale/*.json` 才能通过，待确认（推测：若声明了 `locale` 而不提供字典，至少 `t()` 会缺键）。
3. **样式标签被后续插件 claim 的实际概率**：`claimStyles` 会认领「所有未标记 style」，但真实加载顺序取决于懒加载模块进入时机；是否已在真机 HMR 中造成样式被误删，待确认（推测）。
4. **`conversation.composer.dock` 是否会为非当前会话同时挂载**：若同一时刻存在多个 session 视图，`QQComposerHider` 的全局 `[data-composer-card]` 规则可能跨会话生效；rc.2 的 scope 实现未在本次只读范围内验证（待确认，推测）。
5. **Section 是否必须消费 `close`**：类型上 `close` 是 owner 必填，但本组件参数全 optional，函数参数逆变使其仍可赋值；0.2.1 是否在运行时要求 section 调用 `close`（例如保存后自动关闭），待确认。
6. **`sessions` 服务在 0.2.1 客户端根上下文中的可注入性**：rc.2 的 `ctx.get('sessions')` 与服务名成立，0.2.1 若进一步把选择/列表拆到视图包，`inject: ['sessions']` 需重新核对（待确认）。

## 5. 结论摘要（≤10 条，按优先级排序）

1. **客户端在 0.2.x 仍能显示与保存**（设置页走 REST 自驱动），但**注册层完全绕过 0.2.x 类型**：`ctx: any` + devDeps 仍是 `0.1.5-rc.1`，`pnpm typecheck` 全绿不能证明 0.2.1 对齐。
2. **A3 是唯一已确证的真实运行时失效**：`sessionsSnap.current` 在 0.2.x `SessionListState` 中已删除，`body[data-dsh-napcat-readonly]` 永不设置，全局只读样式成为死规则；目前仅靠 `QQComposerHider` 的会话级样式兜底。
3. **`locale: 'dsh-napcat-bridge'` 是空声明**：无 `LocaleNamespaceMap` 合并、无 `locale/*.json`、无 `t()` 使用，文案全部硬编码；真实类型下注册处会编译失败。
4. **list 槽位多传 `key`**：0.2.x 只认 `id/order/label/priority`，运行时静默忽略，真实类型下会报错。
5. **Section 组件未消费 owner 必填的 `close`**：不是类型错误（参数逆变），但放弃了壳层唯一交互能力（例如保存后关闭面板）。
6. **两处样式注入都错过模块 materialization 窗口**：style 标签无 `data-plugin`，HMR/卸载不清理，且可能被后续插件认领；`injectCardStyles` 还在 render 体内执行。
7. **39/39 测试属于 0.1.5 形状的假绿**：mock `{current}`、用 `initialConfig`+`onSaveSettings` 绕过 REST、只 mock 旧图标名、从未真实渲染 `NapCatSettingsSection`；测试反向固化了空 `locale` 声明。
8. **死代码集中在四条生产不可达通道**：card 折叠布局与图标解析、`controllerRef` 控制器、`onSaveSettings/revision` 保存通道、`useConversation` 回退；另有 `SelectField`、未用样式键、`dist/client/*` 冗余产物。
9. **默认值与错误处理存在漂移**：客户端 `DEFAULT_BASE_CONFIG` 与服务端不一致（`memory_budget_chars` 仅客户端有）；REST 失败丢失服务端文案、无超时/重试/并发保护；`ws_token` 明文且无法清除。
10. **建议顺序**：① 安装 0.2.1 真实依赖并补「真实装配 + 真实类型」契约测试 → ② 删除 body 属性互锁与空 `locale` 声明、修正 list `key` → ③ 清理 card/controller/onSaveSettings 死通道与未用样式、处理样式所有权 → ④ 最后统一默认值来源与敏感字段交互。
