## 1. 背景与根因（用户实测 + 已定位，任务包 §一/§二）

QQ 私聊发文件给机器人，Agent 收到的是一条 `[文件:文件名]` 占位（无本机真实路径），且消息入库时未自动落盘。
根因（行号级实锤）：

1. `src/index.ts` 入站预处理 `file` 段（`:307-310`）只赋值 `dominantType/fileId/busid`，**未触发任何落盘**；
   `image` 段（`:284-306`）有 `mediaManager.downloadAndSave` 即时落盘 + `data.local_path` 回填 —— file 段被跳过。
2. `src/gateway/server.ts` 无 `get_private_file_url` 方法（仅 `get_group_file_url`）。
3. NapCat 源码实证（本机拉取 GitHub main 分支原文件核验）：
   - `packages/napcat-onebot/action/file/GetPrivateFileUrl.ts`：`PayloadSchema` 仅 `{file_id}`，
     返回 `data.url`；`GetPacketStatusDepends` 依赖 packet 后端（QQ 9.9.30-48762 起可能不可用）。
   - `packages/napcat-onebot/action/file/GetFile.ts`：`GetFilePayloadSchema {file?, file_id?}`，
     返回 `data.{file, url, file_size, file_name}`，`data.file` 为 NapCat(Windows) 侧本地路径，**不依赖 packet 后端**。
   - `router.ts` action 字符串实证：`NapCat_GetPrivateFileUrl: 'get_private_file_url'`、`GetFile: 'get_file'`。

## 2. 需求规格落地（用户已拍板，实施严格照此）

### 2.1 接口选型两级退化（任务包 §3.1）
- **首选 `get_private_file_url`**：`data.url`（HTTP 直链）→ `mediaManager.downloadAndSave` 落盘；
  非 HTTP(S) 直链 / status!=ok / 超时异常一律视为首选失败，进入回退。
- **回退 `get_file`**：`data.file`（NapCat 本地路径）→ Windows 盘符路径经 `windowsPathToWsl`
  翻译为 `/mnt/<drive>/...` → `fs.existsSync` 校验 → 拷入 `napcat_download/files/<peer>/`；
  Linux 直落形态路径（已以 `/` 开头）直接校验读取。
- **两路都失败**：返回 `文件下载失败: <首选原因>; <回退原因>`（清晰分环节），**绝不返回占位假路径**；
  消息照常入库但 `local_path` 置空，content 如实标注 `(入站落盘失败)`。

### 2.2 目录约定（任务包 §3.2，沿用现有体系）
- 落盘 `napcat_download/files/<peer>/`（`peer=user_<qq>`），与群文件懒载/工具现拉同目录，不新建目录。

### 2.3 时序与唤醒语义（任务包 §3.3/§3.4）
- 入站 `file` 段且私聊（`message_type !== 'group'`）且非自身发出（`post_type !== 'message_sent'`）
  → `await` 落盘完成后再构建唤醒包/入库（与 image 段同一循环内同步等待）；
- 落盘成功 → `local_path` 回填消息记录 + 唤醒包 content 占位替换为
  `[文件:<名> 已保存: <path>]`（与图片 `[图片:<path>]` atomic 约定同源统一）；
- 群聊 file 段**不改动**（走 group_upload notice 懒载）；
- 自身发出（message_sent）的文件不入站回拉：段内即本机来源路径，无需 NapCat 中转
  （若回拉反而会因 NapCat 无法解析已发送文件而误标失败 —— 实施决策，见 §5）；
- 文件随消息一起决定是否唤醒（私聊默认唤醒，沿用 direct 规则），落盘失败不改变唤醒判定。

## 3. 实现设计

### 3.1 `src/tools/private-file.ts`（新增，两级退化助手）
`downloadPrivateFile({fileId, peer?, busid?, filename?, gateway, mediaManager, logger?})`：

- 前置校验：缺 file_id / gateway / mediaManager → 各自清晰错误；
- 首选：`gateway.getPrivateFileUrl(fileId)` → status ok 且 url 为 `https?://` → `downloadAndSave(url, {fileId, type:'files', sessionId: peer, filename})`；
- 首选失败/异常 → 回退：`gateway.getFile(fileId)` → 提取 `data.file`（`data.url` 兜底本地形态）→
  非 `/` 开头视为 Windows 路径走 `windowsPathToWsl`（翻译失败/文件不存在各给明确原因）→
  `downloadAndSave(wslPath, {…})` 读源拷入 `files/<peer>/`；
- 失败聚合：`文件下载失败: <urlErr>; <localErr>`；`filename` 统一 `path.basename` 规整防路径穿越。
- 纯函数级契约：`windowsPathToWsl` 复用 `src/tools/file-source.ts` 既有实现（零重复代码）。

### 3.2 `src/gateway/server.ts`
新增 `getPrivateFileUrl(fileId)`（action `get_private_file_url`，参数 `{file_id}`）与
`getFile(fileId)`（action `get_file`，参数 `{file_id}`），注释标明 NapCat 源码实证依据与 packet 依赖说明。

### 3.3 `src/index.ts` 入站 file 分支
```ts
dominantType = isGroup ? 'group_file' : 'file';
fileId = data.file_id || data.file || null;
busid = data.busid ?? null;
if (!isGroup && !isSelfMsg && fileId && mediaManager) {
  const pf = await downloadPrivateFile({ fileId, peer, busid, filename, gateway: server, mediaManager, logger });
  if (pf.ok && pf.localPath) { data.local_path = pf.localPath; /* 回填 primaryLocalPath */ }
  else { data.dl_failed = true; logger.warn(...); }
}
```

### 3.4 `src/gateway/wakeup.ts` file 段渲染（content 同源：入库 + 唤醒包）
```ts
if (message_type === 'group')         → [群文件:<名>…]           // 懒载语义不变
else if (data.local_path)             → [文件:<名> 已保存: <path>] // 落盘成功（PF-001）
else if (data.dl_failed)              → [文件:<名> (入站落盘失败)] // 双失败如实标注
else                                  → [文件:<名>]               // 历史/占位回溯
```
附带修复：原判定 `data.busid !== undefined || message_type === 'group'` 会把**带 busid 的私聊
file 段误标为群文件**，改为以 `message_type` 为准（OneBot 11 message 事件恒携带）。
> 文件所有权说明：任务包可改清单含 `src/gateway/server.ts`/`src/index.ts`/`src/tools/*`，
> 本任务另触及 `src/gateway/wakeup.ts`（唤醒包 content 渲染的唯一归属模块，§3.3 硬性要求
> 「唤醒包 content 替换占位为真实路径」必须在此落地；并行提问整改 Agent 不拥有该文件，无冲突）。

### 3.5 `src/tools/index.ts` fetch_chat_resource 私聊分支
非群文件（`user_` 上下文）由原「不支持本地直读」泛化错误 → 走私聊两级退化下载：
`downloadPrivateFile` 成功返回 `{success:true, local_path}`，失败透传分环节错误。
