# 私聊文件入站即时落盘整改 — 提示词

## 任务定位
dsh-napcat-bridge 私有文件入站「占位假成功」接线缺口整改。独立任务，与已有的提问渠道整改（串行多题/群聊引用锚定）**并行不互斥**，文件所有权已与 Agent 错开（见文末）。

## 一、用户实测现象
QQ 私聊发文件给机器人，会话里 Agent 收到的是一条 `[文件:文件名]` 占位（无本机真实路径），且消息入库时该文件**没有自动落盘**。Agent 凭一个文件名无法读取内容。正确行为应为：**私聊文件入站即同步落盘，唤醒包/消息记录给真实本地路径**。

## 二、根因（已定位，行号级）
1. `src/index.ts` 入站预处理 `:278-332`
   - `image` 段（`:284-306`）有 `mediaManager.downloadAndSave` 即时落盘 + `data.local_path` 回填；
   - **`file` 段（`:307-310`）只赋值 `dominantType='file'`、`fileId`、`busid`，未触发任何落盘** → 占位假成功。群文件走 `group_upload` notice 懒载没错，私聊文件被跳过。
2. `src/gateway/server.ts`
   - **无 `get_private_file_url` 方法**（仅 `get_group_file_url` `:281`）；
   - 有不相关的一对 `upload_private_file`/`upload_group_file`（出方向 v2 预留，勿动）。
3. NapCat 源码实证（GitHub `NapCatQQ/packages/napcat-onebot/action/file/`）：
   - `GetPrivateFileUrl.ts`：`file_id` → `FileNapCatOneBotUUID.decode` → 反查 msg 拿 file hash → `PacketApi.pkt.operation.GetPrivateFileUrl`；**依赖 packet 后端**（`GetPacketStatusDepends`），失败抛 `real fileUUID not found!`。
   - `GetFile.ts`：走 `FileApi.downloadMedia`，**不依赖 packet 后端**，对 file_id/file 返回 NapCat(Windows) 侧本地路径 `{file, url, file_size, file_name, base64}`。
   - ⚠️ GitHub issue **#1852**：QQ 升到 `9.9.30-48762` 后 packet 后端不可用，`get_private_file_url` 取直链直接失败（和 send_poke 同源）。send_poke 已有先前踩坑先例。

## 三、需求规格（用户已拍板）
### 3.1 接口选型（用户定，两级退化）
- **首选 `get_private_file_url`**：拿 `data.url`（HTTP 直链）→ 插件侧 `downloadAndSave` 落盘。
- **回退 `get_file`**（首选失败/packet 不可用时）：拿 NapCat 本地路径 → `windowsPathToWsl` 翻译为 `/mnt/<drive>/...` → 校验存在 → 拷入 `napcat_download/files/<peer>/`（或读取其内容存盘）。
- **两路都失败**：返回清晰错误（`文件下载失败: <具体环节原因>`），绝不返回占位假路径；消息照常入库但 `local_path` 置空，如实标注"入站落盘失败"。

### 3.2 目录约定（沿用现有体系，不新建）
- 私聊文件落盘到 `napcat_download/files/<peer>/`（peer=`user_<qq>`）。与群文件懒载/工具现拉同目录，靠 peer 区分群/私聊，不新增 `private_files/` 之类目录（现有命名已够用）。

### 3.3 时序（用户定：同步落盘成功再唤醒）
- 入站 `file` 段且**私聊**（`!isGroup`）→ **await 落盘完成**后才构建唤醒包/入库。
- 落盘成功后把 `local_path` 回填进消息记录 `local_path` 字段 + 唤醒包 content 里替换文件占位为真实路径（如 `[文件:${fileName}]` → `[文件:${fileName} 已保存: ${localPath}]` 或直接给真实路径，格式按现有图片/文件 atomic 约定统一）。
- 群聊 file 段保持现状（走 group_upload notice 懒载，不动）。

### 3.4 唤醒语义
- 文件随消息一起决定是否唤醒（私聊默认唤醒，沿用现有 direct 规则），不得因落盘失败改变唤醒判定。

## 四、契约测试（TDD 必须）
- 真实装配路径：contract 测试断言「私聊入站 file 段 → 触发 get_private_file_url（mock 网关隔离网络）→ downloadAndSave 落盘成功 → 消息记录 local_path 非空」。
- 退化路径：get_private_file_url 返回失败/failed → 回退 get_file → 翻译 WSL 路径 → 落盘成功。
- 双失败：断言返回清晰错误、local_path 为空、不抛未捕获异常。
- 群聊 file 段：断言**不**触发私聊落盘逻辑（保持懒载）。
- 严禁 mock 桩冒充装配：mock 仅限隔离外部网络/第三方，装配路径须真。
