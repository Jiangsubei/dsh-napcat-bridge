# 任务包：记忆工具重构 read/edit/create（对齐 DSH edit 模型）

> **项目**: dsh-napcat-bridge  
> **日期**: 2026-09-06  
> **优先级**: P1  
> **背景**: 现有 read_memory / append_memory / update_memory 三工具。append(追加)+update(全量重写) 语义不清晰，改/删/加纠缠。重构为 read_memory / create_memory / edit_memory，对齐 DSH `dsh-tool-fs` 的 read/write/edit 模型。

---

## 1. 目标

| 现状 | 重构后 |
|---|---|
| `read_memory` | `read_memory`（保留，语义补全） |
| `append_memory`（末尾追加条目） | ❌ 删除，并入 `edit_memory` |
| `update_memory`（全量重写） | ❌ 删除，并入 `edit_memory` |
| — | `create_memory`（仅当文件不存在） |
| — | `edit_memory`（定向字面替换 / 删除） |

**核心机制变动**：
1. **删除 `lastReadContent`（write-before-read 门控 + "必须先 read"）** → 改为 DSH 式 **old_string 写时唯一匹配自校验**
2. **storage 哑化**：不再自动加 ISO 时间戳前缀、不再自动补 `# 用户画像/`# Session 记忆` 头；create 原样写入 agent 提供的 content
3. **`edit_memory` = 定向字面替换**：`old_string` → `new_string`，`new_string` 省略/空 = 删除匹配片段；要求唯一匹配

## 2. 设计定稿

### 2.1 通用

- `type: 'session' | 'user'`（必填）
- 标识解析（沿用 `resolveUserTarget` 思路）：
  - `type='session'` → 用 `peer`（必填，无 peer 拒绝）
  - `type='user'` → 归一化 qq：显式 `qq` > `peer` 的 `user_` 前缀派生 > 报错（**不再退回 default**）
- 保留现有「exec 解析为 default 且未显式传参 → 拒绝」的 execute 层保护

### 2.2 `read_memory`（保留）
```ts
read_memory { type, peer?, qq? }
```
- 文件存在 → `{ success: true, type, target, content }`（content = 全文）
- 文件不存在 → `{ success: true, type, target, content: '' }`（**不报错**，agent 据此判断 create）
- 错误：标识缺失；type 非法

> ⚠️ **read 语义必须返回目标文件真实内容**。storage 现有的 `readUserProfile` 带 `user/default.md` 回退——read_memory 应使用**不回退**的 raw 读取（否则 agent 读到 default.md 误以为画像存在就不创建了）。default.md 回退逻辑**只保留在 prompt 注入层**（`getPromptSnapshotSync`），不经过 read_memory。

### 2.3 `create_memory`（新增）
```ts
create_memory { type, peer?, qq?, content }   // content 必填
```
- 文件不存在 → **原样写入** `content`（无时间戳、无头）→ `{ success: true, type, target }`
- 文件已存在 → 拒绝：`"目标记忆已存在，请使用 edit_memory 修改，不要重复创建。"`
- 错误：content 为空 `"创建内容不能为空。"`；标识缺失；type 非法

### 2.4 `edit_memory`（新增，核心）
```ts
edit_memory { type, peer?, qq?, old_string, new_string? }   // old_string 必填；new_string 省略/空 = 删除
```
内部（对齐 DSH `replaceInFile`）：
1. 读当前文件
2. 找 `old_string` 所有出现位置
3. 未出现 → 报错；出现 ≥2 次 → 报错
4. 唯一 → 替换为 `new_string`（空/省略 = 删除匹配片段）
5. atomicWrite 落盘，emit `memory/change`

**返回**（成功）：`{ success: true, type, target, preview }`（preview = 变更处前后各 ~30 字符片段，**不回全文**）

**错误**（完整文案）：
- 未找到：`"old_string 未在当前记忆中找到，可能内容已变化，请先 read_memory 获取最新内容。"`
- 多义：`"old_string 出现 N 次，请补充更多上下文使其唯一。"`（N 为实际次数）
- 文件不存在/为空：`"目标记忆不存在，请先 create_memory 创建。"`
- `old_string` 为空：`"old_string 不能为空。"`
- 标识缺失 / type 非法

### 2.5 storage 哑化（src/memory/storage.ts）

**删除**：
- `appendSessionMemory`（line 81）
- `appendUserProfile`（line 127）
- 时间戳生成代码（`new Date().toISOString().replace(...)`）

**保留**：
- `writeSessionMemory` / `writeUserProfile`（已是原样写入）
- sync 读写、路径、缓存

**新增**：
- `readSessionMemoryRaw` / `readUserProfileRaw`（**无 default.md 回退**，供 tools 用；现有 readSessionMemory 本就无回退，readUserProfile 需加 raw 版）
- `existsSessionMemory(peer)` / `existsUserProfile(qq)`（供 create 判断）

### 2.6 prompt 注入无头补标（src/memory/storage.ts `getPromptSnapshotSync`）

现在 create 不再自动加 `#` 头 → 新文件可能无头。注入时：
- session 记忆：若内容不以 `#` 开头，补 `### Session 记忆（${peer}）\n${content}`；已有 `#` 头则原样（沿用现有 user 画像的 `startsWith('#')` 判断逻辑到 session）
- user 画像：已有逻辑（`profile.startsWith('#') ? profile : '### name (qq)\n' + profile`），保持不变
