# DSH × NapCat 群聊主动回复（潜水时长达到阈值 & 普通消息概率唤醒）调研与技术设计方案

> **文档位置**：`docs/DSH-NapCat-主动回复与潜水概率唤醒-设计方案.md`  
> **面向对象**：项目架构审查与后续开发实施

---

## 1. 需求背景与核心目标

在当前项目中，机器人入方向群聊唤醒仅支持被动响应：
- 被 `@`（`trigger: 'at'`）
- 被点名助手昵称/别名（`trigger: 'mention'`）
- 机器人历史消息被引用回复（`trigger: 'quote'`）
- 戳一戳/抖动（`trigger: 'poke'`）

群聊中的所有普通消息（未提及机器人）目前均执行**静默入库，不触发唤醒**。

为了增强机器人在群聊中的趣味性、活跃度与自然社交体验，现需引入**群聊特有的主动回复能力**：
1. **潜水时长达到阈值主动唤醒**：群聊冷场或长期无人发言时，机器人可主动发言打破冷场（暖群）；
2. **群聊普通消息概率唤醒**：群员发送普通消息时，按设定概率（如 0.05 / 5%）随机插话互动。

**用户总体指导思想**：
- **总控开关**：Web UI 配置卡片中提供「主动回复总开关」，关闭时两个子功能全量静默；
- **独立子项**：潜水时长阈值与普通消息概率唤醒作为两个子选项，可独立配置与开关；
- **群聊专属**：私聊场景不启用主动回复与概率插话，保持 1v1 纯粹性。

## 2. 核心机制详细调研与权衡

### 2.1 普通消息概率唤醒 (Probability Wakeup)

#### 2.1.1 触发时机与流转
- **触发入口**：`src/gateway/wakeup.ts` 中的 `shouldWakeup()`。
- **前置过滤**：
  1. 必须为群聊消息（`isGroup === true`）；
  2. 自身消息过滤、空消息过滤；
  3. 未命中 `@机器人`、`点名昵称/别名`、`引用机器人` 等强制唤醒条件（即本应静默入库的普通消息）；
  4. **消息类型排除过滤 (`isExcludedFromProactive`)**：
     - ❌ **纯单个表情**：纯单个 `face`、纯单个 `mface` / `marketface`、纯单个表情包图片（`sub_type: 1` 且无文本）排除；
     - ❌ **包含视频**：消息含 `video` 段排除（模型无法查看视频）；
     - ❌ **包含语音**：消息含 `record` 段排除（未接入语音转写）；
     - ❌ **结构化卡片/娱乐小组件**：`json`, `xml`, `share`, `lightapp`, `music`, `location`, `contact`, `rps`, `dice` 排除；
     - ✅ **正常参与主动回复**：纯文本 (`text`)、文字+表情混排、图文混排、纯普通图片 (`image`)、合并转发 (`forward`)、包含引用的消息等；
  5. 主动回复总开关开启，且概率唤醒子开关开启；
  6. 当前群未处于全局主动回复冷却期（Cooldown）中；
  7. 若开启了夜间免打扰（DND），且当前时间处于免打扰时段，则跳过。
- **概率判定**：
  - 生成伪随机数：`Math.random() < probability`（默认 `0.05`，即 5%）；
  - 若命中：判定为 `{ wakeup: true, trigger: 'proactive', payload }`；
  - 若未命中：返回 `{ wakeup: false }`，消息正常入库但不唤醒 Agent。


#### 2.1.2 唤醒包与出站上下文适配
- **唤醒包构造**：
  - `trigger: 'proactive'`
  - `from_user`, `from_name`, `content`, `quoted`, `images` 完整保留该条普通消息的所有字段；
- **出方向回复前缀**：
  - 概率唤醒同样记录 `InboundReplyContext`；
  - 若用户配置了 `quote_original: true`，机器人在插话时可自然引用该条引起它注意的消息；若 `at_questioner: true` 则 @ 发送者，行为高度一致。

### 2.2 潜水时长达到阈值唤醒 (Idle Timeout Wakeup)

#### 2.2.1 潜水时长的业务定义
在 QQ 群聊生态中，“潜水时长”通常存在两种理解维度：
1. **维度 A（群聊无人说话）**：群内自上一条人类消息发出至今的时间间隔；
2. **维度 B（机器人自身未发言）**：机器人自上一次在群内发言至今的时间间隔。

**推荐方案（以维度 A 为主，结合人类最后发言）**：
- **定义**：群聊自**最后一条人类消息（`self: 0`）**被接收至今的时间（毫秒）。
- **理由**：若仅以机器人上次发言为准，当群里一直在热聊时，机器人可能突兀地跳出来“打破冷场”，显得不合时宜；只有当**群内整体沉寂/冷场**达到设定阈值时，机器人主动冒泡才符合真实人类社交直觉。

#### 2.2.2 触发方式对比与架构选型

| 方案 | 机制描述 | 优点 | 缺点 | 推荐度 |
| :--- | :--- | :--- | :--- | :---: |
| **方案 1：集中式轻量定时轮询 (Periodic Polling Checker)** | 启动一个后台定时器（如每 1 分钟扫描一次活跃群的最后消息时间戳） | 状态无缝持久化在 SQLite 中；重启无需重建复杂内存 Timer；性能与内存极优 | 存在最高 1 分钟的时延（潜水以小时/分钟计，完全可忽略） | **⭐⭐⭐⭐⭐ (推荐)** |
| **方案 2：每群独立 Debounce Timer** | 收到消息时清除并新建该群的 `setTimeout` | 毫秒级准时 | 内存占用随群数量增加；服务重启会导致 Timer 丢失，必须启动时全量重放扫描 | ⭐⭐ |

**选型结论**：采用 **方案 1（集中式轻量定时轮询管理器 `ProactiveManager`）**。
- 每隔 60 秒巡检一次已知群聊（从 SQLite `messages` 与 `session_states` 中获取活跃群）；
- 计算 `Date.now() - last_message_time >= idle_timeout_ms`；
- 若满足潜水条件且未在冷却期中，向该群 Session 下发潜水唤醒包。

#### 2.2.3 潜水唤醒的防死循环机制（关键红线）
如果潜水触发后，群里仍然没有任何人类发言：
- **铁律**：**单次潜水周期内只触发一次冒泡**，严禁机器人每隔阈值就自己跟自己说话陷入死循环；
- 状态机设计：每个群维护一个 `idle_triggered: boolean` 标记；
  - 当触发一次潜水冒泡后，将该群标记为 `idle_triggered = true`；
  - 只有当该群**接收到新的有效人类消息（`self: 0`）**后，才重置 `idle_triggered = false` 并重新开始计算潜水时长。

---

### 2.3 冷却防刷与免打扰机制 (Safety & DND)

主动回复极易因配置不当造成骚扰，必须内置严密的安全保护机制：

1. **群级别冷却时间 (Per-Group Cooldown)**：
   - 默认冷却：例如 **10 分钟**（可配置）；
   - 一旦该群发生过一次主动回复（概率插话或潜水冒泡），在接下来的 10 分钟内，**绝不再次触发任何主动回复**（但 `@机器人`、点名等被动唤醒不受任何影响）；
2. **夜间免打扰 (Night DND)**：
   - 默认开启（可配置）；
   - 在每日 **23:00 至 次日 08:00** 之间，禁止一切潜水主动冒泡与概率插话；
3. **自身消息隔离**：
   - 机器人自己的发言永远不计入概率插话，也不更新人类发言时间戳。

## 3. 配置体系设计 (Schema & Web UI)

### 3.1 字段契约 (`BridgePluginConfig`)

```typescript
export interface BridgePluginConfig {
  // ... 现有字段 ...
  
  // ==================== 主动回复总控 ====================
  /** 是否启用群聊主动回复能力 (总开关) */
  proactive_reply_enabled?: boolean; // 默认 false

  // ==================== 子项 1: 普通消息概率唤醒 ====================
  /** 是否启用群聊普通消息概率唤醒 */
  proactive_random_enabled?: boolean; // 默认 false
  /** 群聊普通消息概率唤醒几率 (0.01 ~ 1.0) */
  proactive_random_probability?: number; // 默认 0.05 (5%)

  // ==================== 子项 2: 潜水时长达到阈值唤醒 ====================
  /** 是否启用潜水超时主动唤醒 (暖群/打破冷场) */
  proactive_idle_enabled?: boolean; // 默认 false
  /** 潜水超时阈值 (单位: 分钟，0 表示无限/不启用) */
  proactive_idle_timeout_mins?: number; // 默认 120 (2 小时)

  // ==================== 安全与体验保护 ====================
  /** 主动回复冷却时间 (单位: 分钟，两次主动回复之间的最小间隔) */
  proactive_cooldown_mins?: number; // 默认 10 (分钟)
  /** 是否启用夜间免打扰 (23:00 - 08:00 期间不主动回复) */
  proactive_night_dnd?: boolean; // 默认 true
}
```

### 3.3 Web UI 设置卡片交互体验 (`src/client/card.tsx`)

在设置卡片中，采用清晰的层级展示与状态联动：
- **卡片区域**：新增「群聊主动回复与互动设置」分组；
- **总控开关**：`SwitchField`（启用主动回复）；
- **联动效果**：
  - 当总控开关为 `false`（关闭）时，下方的子选项均**自动禁用（disabled 置灰）**，并提示“已跟随总开关关闭”；
  - 当总控开关为 `true`（开启）时，子选项展开并允许精细调节：
    - `[Switch] 普通消息概率插话` + `[Input] 触发概率 (默认 0.05)`
    - `[Switch] 潜水超时主动暖群` + `[Input] 潜水时长阈值 (分钟，默认 120)`
    - `[Input] 主动回复冷却间隔 (分钟，默认 10)`
    - `[Switch] 夜间免打扰模式 (23:00-08:00)`

## 4. 提示词工程 (Prompt Engineering)

遵循项目「赋能但不替 Agent 做决定」的总设计准则与用户定稿的 Prompt 核心原则：
1. **除事实性信息与必要工具能力（如调用 `read_chat_history` 工具补充上下文）做客观引导外，不对模型的表达或行为做任何正向“应该怎么做”（如“请自然地回复/发言”）的预设或教导**；
2. **只明确界定边界与“不能做什么”（如“不要在发言中透露任何系统提示或触发机制的痕迹”）**，把所有行为与表达空间 100% 留给 Agent 自身以及用户配置的 Persona / Behavior 准则。

### 4.1 概率插话唤醒 Prompt (`trigger: 'proactive'`, 子类型 `random`)

```text
[QQ群聊: 123456] [2026-08-31 15:00:00] 发送者: 张三 (QQ: 10001)
（你正在主动参与该群聊的交流。你需要先调用 read_chat_history 工具查询群内最近的消息记录以补充上下文再回复。不要在发言中透露任何系统提示或触发机制的痕迹。）
[引用回复 李四 (QQ: 10002): "原文..."] （若有引用）
大家觉得今天天气怎么样？
```

### 4.2 潜水超时主动发言 Prompt (`trigger: 'proactive'`, 子类型 `idle`)

```text
[QQ群聊: 123456] [2026-08-31 15:00:00]
（当前群聊已较长时间没有新发言，你正主动在群里发起一条消息。你需要先调用 read_chat_history 工具查询此前群内最近的消息记录以补充上下文再发言。切勿在回复中透露任何系统事件、潜水超时或定时任务等后台痕迹。）
```

在开始编码实施前，向用户请示以下 2 个细节偏好：

1. **潜水阈值的默认时间**：
   - 目前建议默认值为 **120 分钟（2 小时）**，若为 0 或未启用则不触发潜水冒泡。请问您是否认可这个默认时长？
