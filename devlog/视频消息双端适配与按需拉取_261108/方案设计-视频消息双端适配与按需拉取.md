> **设计日期**：2026-11-08  
> **状态**：待实施（遵循 TDD 规范，先行契约测试再落代码）  
> **基准协议端**：NapCat.Onebot v4.18.42  
> **兼容协议端**：SnowLuma v2.4.0-node（提供异常处理与降级垫片）

## 1. 需求与设计目标

### 1.1 现状与痛点
- QQ 发送视频时，Agent 收到的是一律写死的占位符 `[视频]`；
- 模型无法获知视频的远端 ID，也无法在需要时调取视频内容；
- 群聊若默认下载所有视频，会造成严重的带宽拥堵、磁盘爆满与网关超时；
- 私聊若不默认下载，模型需多花一轮 tool_call 先下载再消费，交互链路冗长且体验割裂。

### 1.2 优化目标
1. **群聊按需拉取**：
   - 群聊入站**不默认下载**任何视频，避免流量与资源浪费；
   - 提取段内的 `data.file` 作为 ID，渲染为 `[视频 (ID: <file_id>)]` 或 `[视频: <file_name> (ID: <file_id>)]`；
   - 模型在需要分析视频时，主动调用 `fetch_chat_resource(file_id)` 工具按需拉取。
2. **私聊即时落盘**：
   - 私聊入站即时下载视频至本地附件目录（`files/<peer>/`）；
   - 渲染为 `[视频 已保存: <local_path>]` 或 `[视频: <file_name> 已保存: <local_path>]`；
   - 模型在第一轮即可直接通过本地物理路径调用工具/脚本消费。
3. **双端平滑兼容（NapCat 为基准 + SnowLuma 垫片）**：
   - 鉴于实测实证 SnowLuma 的 `get_file` 不支持视频，拉取群视频时采取“**段内直链优先 -> `get_file` 回退刷新**”策略；
   - 直链由 `multimedia.nt.qq.com.cn` 承载，双端原生通用；
   - 若直链过期且处于 SnowLuma 环境，提供清晰友好的错误说明垫片。

## 2. 详细设计与关键契约

### 2.1 统一附件渲染契约（`render.ts` 与 `wakeup.ts`）
渲染规则扩充 `case 'video'`：
- 若具备 `descriptor.local?.path`（本地已落盘）：
  - 格式：`[视频${namePart} 已保存: ${descriptor.local.path}]`
- 若仅具备 `descriptor.remote?.fileId`（群聊待拉取）：
  - 格式：`[视频${namePart} (ID:${descriptor.remote.fileId})]`
- 若标记 `unavailable`（落盘失败）：
  - 格式：`[视频${namePart} (入站落盘失败)]`
- 兜底：
  - 格式：`[视频]`

其中 `${namePart}`：若有合法 `descriptor.fileName`，且与 `fileId` 不重复，则拼为 `:${fileName}`；若没有独立文件名或与 ID 相同，则保持简短。

### 2.2 入站预处理与私聊即时落盘（`src/index.ts`）
在入站消息遍历时：
- 识别 `seg.type === 'video'`：
  - 在**私聊**环境（`!isGroup && !isSelfMsg && mediaManager`）：
    - 优先尝试段内 `data.url` 直链下载（`mediaManager.downloadAndSave`）；
    - 若直链缺失或失败，回退调用 `downloadPrivateFile`（走 `get_file`）；
    - 成功则写入 `data.local_path = saved.localPath` 与 `data.fingerprint`；
    - 失败则标记 `data.dl_failed = true`；
  - 在**群聊**环境（`isGroup`）：
    - 不触发下载，保留段内元数据供 `describeSegment` 提取。

### 2.3 工具扩充：`fetch_chat_resource` 支持群视频按需拉取（`src/tools/index.ts`）
在 `fetchSingleChatResourceItem` 中：
- 现行逻辑：在群聊上下文中（`isGroupFile = true`），若 `busid` 缺失则抛错。
- **重构逻辑**：
  - 若处于群聊上下文，但 `item.busid === undefined || item.busid === null`：
    - 判定为**群聊天流富媒体/视频**（而非群文件系统文件）；
    - **第一步：直链首选**：从数据库 `messages` 表查出该 `file_id` 对应的记录，从 `attachments` 提取 `remote.url`；
      若有有效 HTTP(S) 直链，直接调用 `mediaManager.downloadAndSave(url, ...)`；
    - **第二步：NapCat `get_file` 回退刷新**：
      若直链失效或缺失，调用 `gateway.getFile(fileId)` 获取最新刷新地址或本地路径并落盘；
    - **第三步：SnowLuma 垫片**：
      若 `gateway.getFile` 抛错或返回 `retcode: 100`（SnowLuma 特征），捕获并返回更友好的提示信息。
