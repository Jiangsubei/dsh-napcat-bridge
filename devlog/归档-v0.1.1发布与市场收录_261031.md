### 4.4 为什么必须是 optional（关键决策，勿回退）

`cordis.patch.yml` 内嵌 `qq-session` 预设，引用 12 个 `@deepseek-ai/*` 包。若**非 optional** 声明：

- `@deepseek-ai/dsh-tool-working-directory` 从未发布稳定版，registry `latest` 恒为 `0.2.1-alpha.2`
- 该版本 peer 要求 `dsh-tools@0.2.1-alpha.2`，而宿主 `dsh-base@0.2.0-rc.2` 要求 `dsh-tools@0.2.0-rc.2`
- 实测 `npm install` 直接 **ERESOLVE 失败**（9 条间接冲突）

标记 `optional: true` 后：声明语义保留、不自动安装、安装恢复正常。

## 七、发布流程中的坑（务必记住）

### 7.1 npm 新版发布是异步落地，会先出现 `0.0.0-stage`

`npm publish` 返回 `+ dsh-napcat-bridge@0.1.1` 且 exit 0 后：

1. registry 立即出现占位版本 `0.0.0-stage`，readme 被替换为 "Temporary package placeholder for staged publishing"
2. `dist-tags.latest` 指向 `0.0.0-stage`，`versions` 只有它
3. `npm stage list` 返回 `[]`（staging API 无记录）
4. 此时重发会报 `You cannot publish over the previously published versions: 0.1.1`

**约 2 分钟后自动生效**：`versions` → `['0.0.0-stage','0.1.1']`，`latest` → `0.1.1`。

**处置原则**：等待 2–5 分钟后复查，**不要改版本号、不要反复重发**。

### 7.2 2FA / token

- 当前 granular token **可直接 `npm publish`**，无 OTP 交互
- `npm profile get` 返回 403（GAT 无账号级权限），属正常
- npm 公告：bypass-2FA token 的直接发布能力将于 **2027 年 1 月**移除，届时需迁移到 trusted publishing 或 2FA

### 7.3 本机无 `dsh` CLI

DSH 为 Desktop 版（`F:\Apps\DeepSeek Harness`），`desktop` profile 由 Electron 独占，CLI 拒绝管理。所有 Desktop 侧操作只能走 GUI。
