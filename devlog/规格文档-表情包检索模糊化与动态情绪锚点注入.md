## 1. 背景与核心动机

在当前的 Agent 运行机制下，表情包工具套件（`list_faces`, `send_face`, `collect_face`, `manage_faces`）存在两大约束：
1. **盲盒困境（冷启动无锚点）**：模型在会话启动和对话推进过程中，上下文中缺乏表情包库容与情绪分类的感知，不知道当前库里有多少张表情、具备哪些情绪，导致其无法主动判断何时发表情，或盲目猜测情绪进行检索引发多次空查询；
2. **硬编码精确匹配导致的高脱靶率**：
   - 现有的 `mood` 检索采用严格等值匹配（`WHERE mood = ?`），字面微小差异（如“调侃” vs “调侃/幽默”）即导致查空；
   - 现有的 `tag` 检索采用带双引号的 JSON 精准匹配（`tags LIKE '%"<tag>"%'`），无法匹配包含子串（如用“猫”去匹配“可爱猫猫”直接失败）；
   - 缺少一站式的模糊自由词检索参数 `query`。

本项目为多模态智能体架构，多模态模型在收录（`collect_face`）时已具备自动提取画面与梗词为标签的能力，因此无需引入沉重的 OCR 管道。通过**建立会话动态情绪锚点**与**底层检索模糊化增强**，即可用极简的代码改造彻底打通模型“知库 -> 查库 -> 发图”的高效闭环。

## 2. 详细设计规格

### 2.1 模块一：数据库存储层模糊匹配与统计能力 (`src/storage/database.ts`)

#### 2.1.1 检索逻辑改造 (`queryFaces`)
- **扩展入参**：在 `FaceQueryOptions` 中引入可选的自由模糊词 `query?: string`；
- **Mood 模糊化**：从 `WHERE mood = ?` 调整为 `WHERE mood LIKE ?`，参数传入 `\`%${mood.trim()}%\``；
- **Tag 模糊化**：去除死板的包含双引号格式，调整为 `tags LIKE ?`，参数传入 `\`%${tag.trim()}%\``；
- **综合模糊检索 `query`**：若提供了 `query` 参数，且非空字符串，生成 `(tags LIKE ? OR mood LIKE ?)` 条件，双字段同时匹配子串；
- **向后兼容**：保留既有 `untagged`, `enabledOnly`, `limit`, `offset`, `orderBy`, `order` 等所有原有逻辑与契约。

#### 2.1.2 表情库概况与情绪聚合统计 (`getFaceMoodSummary`)
在 `MessageDatabase` 中新增轻量只读统计方法：
```typescript
export interface FaceMoodSummary {
  total: number;
  moods: Array<{ mood: string; count: number }>;
}

getFaceMoodSummary(limitMoods: number = 8): FaceMoodSummary
```
- **实现 SQL**：
  1. 总量统计：`SELECT COUNT(*) as total FROM faces WHERE deleted_at IS NULL AND enabled = 1`；
  2. 情绪聚合：
     ```sql
     SELECT mood, COUNT(*) as cnt
     FROM faces
     WHERE deleted_at IS NULL AND enabled = 1 AND mood IS NOT NULL AND TRIM(mood) != ''
     GROUP BY mood
     ORDER BY cnt DESC
     LIMIT ?
     ```
- **耗时与资源**：SQLite 索引与单表小数据量（<= 100 条）执行耗时 < 1ms，极度轻量。

### 2.2 模块二：动态 System Prompt 情绪锚点注入 (`src/prompt/dynamic.ts` & `src/index.ts`)

#### 2.2.1 注册独立的表情包动态段
- **段名称**：`napcat:face_summary`
- **优先级 Order**：`48`（位于 `napcat:slang` (45) 之后、`napcat:behavior_persona` (50) 之前）
- **触发门控**：
  - 仅在 `isQQSession`（QQ 场景会话）下生效；
  - 仅在全局配置 `face_enabled: true` 时生效；
  - 非 QQ 场景或功能关闭时返回空字符串，不产生任何上下文干扰。

#### 2.2.2 注入文本规格与 Token 预算保护
- **总预算**：控制在 30 ~ 60 Token 内（约 1 ~ 2 行文本）；
- **有表情包库存时**：
  ```text
  [本地表情库概览：共 N 张表情包。当前可用情绪：卖萌(X), 调侃(Y), 无奈(Z), 赞同(W)。表达相应情绪时，可直接使用对应 mood 调用 list_faces 查询并配合 send_face 发送。]
  ```
- **表情库为空时（总数为 0）**：
  ```text
  [本地表情库概览：当前库为空。若聊天中出现有趣的梗图或表情，可调用 collect_face 进行收录打标。]
  ```

### 2.3 模块三：Agent 工具参数与定义升级 (`src/tools/index.ts`)

#### 2.3.1 `list_faces` 工具 Schema 升级
- **更新参数契约**：
  - `query` (string, 可选): `综合模糊检索关键词，同时匹配表情的情绪或标签内容（如 "猫猫", "问号", "委屈"）`；
  - `mood` (string, 可选): `按情绪或语境筛选（支持包含匹配，如 "嘲讽", "卖萌", "赞同", "无奈", "开心"）`；
  - `tag` (string, 可选): `按画面元素或文字标签筛选（支持包含匹配，如 "猫猫", "熊猫头", "问号"）`；
  - `untagged` (boolean, 可选): `是否只检索尚未打标的表情`；
  - `limit` (number, 可选): `返回数量上限 (默认 100，上限 100)`。
- **向下完全兼容**：旧调用传 `mood` 或 `tag` 无需任何改动，且原本容易脱靶的传参自然转为命中。

## 3. 契约测试与验证方案 (TDD)

按照项目契约测试保护红线与装配闭环要求，编写严格的契约测试：
1. **数据库层单测与契约**：
   - 验证 `queryFaces({ mood: "调侃" })` 可成功匹配 `mood: "调侃/搞笑"`；
   - 验证 `queryFaces({ tag: "猫" })` 可成功匹配 `tags: ["可爱猫猫"]`；
   - 验证 `queryFaces({ query: "委屈" })` 可在 tags 中命中、亦可在 mood 中命中；
   - 验证 `getFaceMoodSummary()` 聚合统计正确性（按数量降序、过滤空值与已停用表情）。
2. **动态 Prompt 注入装配测试**：
   - 验证在 `face_enabled: true` 下，QQ 会话能正确渲染出 `[本地表情库概览...]` 文本；
   - 验证在空库状态下，能够友好输出收录引导文案；
   - 验证在 `face_enabled: false` 或非 QQ 会话下，返回空文本。
3. **Agent 工具集装配测试**：
   - 验证通过 `toolsService.get('list_faces').execute({ query: "..." })` 返回符合 DSH Lossless JSON 约束。
