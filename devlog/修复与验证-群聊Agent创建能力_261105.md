# 修复与验证：群聊 Agent 创建能力（create_target_agent）

> 日期：2026-11-05　状态：已实现并通过契约测试与构建（待真机验收）

## 1. 问题现象

真实会话中，Agent 被要求「去某个群里发 1」时：

1. 调用创建工具后生成的是 `user_<群号>` / `qq-user-<群号>` 的私聊会话，而非 `group_<群号>` / `qq-group-<群号>`；
2. 该私聊会话是一个空转僵尸会话，没有任何真实私聊消息；
3. 再尝试 `send_agent_message({ target_session_id: 'qq-group-<群号>' })` 被拦截：
   「目标 Agent 会话 [...] 尚未激活或不存在。若需要为该用户建立专属会话，请先调用 create_user_agent 创建并激活。」
4. 但 `create_user_agent` 只能建私聊，形成死循环 —— 群会话永远无法由内部主动冷启动，
   只能等群里出现真实入站消息。

## 2. 根因

不是 peer 解析把 `group_` 误判成 `user_`，而是**创建工具的契约从设计上就只支持私聊**：

- `create_user_agent` 参数只有 `user_id`；
- 实现硬编码 `const peer = 'user_' + user_id`，无任何 group 分支；
- 也不校验该纯数字 ID 是 QQ 号还是群号（两者在本地无法区分）；
- 因此 Agent 把群号当 `user_id` 传入必然落成私聊会话。

此外：

- `send_agent_message` 对未激活会话的前置校验是硬拦截，且错误文案指向只能建私聊的旧工具；
- 全仓库无删除/归档会话的工具，误建会话无法清理。

## 3. 变更

### 3.1 统一创建工具：`create_target_agent`

- 删除 `create_user_agent`（按用户决定，不保留兼容别名）；
- 新契约：

```ts
interface CreateTargetAgentParams {
  target_type: 'user' | 'group'; // 必填，显式区分
  target_id: string | number;    // QQ 号或群号（纯数字）
  initial_message: string;
}
```

- `target_type` 缺失或非法时直接拒绝，绝不猜测默认值：
  「target_type 必须显式指定为 "user" 或 "group"，以避免把群号误当 QQ 号建成私聊会话」；
- `target_id` 校验纯数字；
- peer 按 `user_<id>` / `group_<id>` 严格构造，Session 走 `peerToSessionId`，
  群目标即 `qq-group-<群号>`；
- 创建前仍通过 `ensurePeerName` 预热群名/昵称（标题不以纯号码起步）；
- 目标已存在时返回 `created: false` 与 Session ID，不重复注入初始消息。

### 3.2 使用边界

按用户要求：

- **不做存在性校验**（不查 `get_group_info` / 好友列表）—— 允许为临时会话、尚未出现在好友列表中的号码建会话；
- **仅在用户明确指定目标对象**（谁 / 哪个群）时才主动创建；该约束写入：
  - `QQ_PRESET_PERSONA_PREFIX` 协同段落；
  - `create_target_agent` 工具描述。

### 3.3 配套调整

- `send_agent_message` 未激活拦截文案改为提示调用 `create_target_agent`
  （按 `target_type` 显式区分 user/group）；
- `list_active_agents` 空列表提示改为 `create_target_agent`；
- `src/types/index.ts`、`src/tools/index.ts` 导出与注册同步重命名；
- `cordis.patch.yml` 随预设变更重新生成。

## 4. 测试

- 契约 2 新增「群聊创建契约」：`target_type: 'group'` → `peer = group_8000000002`、

- 真实装配契约断言注册表包含 `create_target_agent`；
- `send_agent_message` 未激活错误文案断言改为 `create_target_agent`。
