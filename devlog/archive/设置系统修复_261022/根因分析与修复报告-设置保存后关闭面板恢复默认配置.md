# 根因分析与修复报告：设置保存后关闭面板恢复默认配置

> 归档日期：2026-10-22  
> 责任代理：Antigravity  
> 问题现象：修改配置后点击保存，关闭设置面板再重新打开时恢复为默认配置。

---

## 1. 根本原因深度分析

### 1.1 `bot_qq` 缺少 `.volatile()` 导致 DSH 0.2.1 持久化拦截
在 DSH 0.2.1 规范中，设置系统的表单生成和修改由 `@deepseek-ai/dsh-settings`（`SettingsForms`）统一托管。
- 依据 `dsh-settings/lib/index.js`（第 505-520 行）：
  ```javascript
  const form = volatileForm(schema);
  if (form === void 0) throw new Error(`Plugin entry "${ns}" has no volatile fields`);
  for (const path of paths) {
    if (path.length && !isVolatilePath(schema, path)) {
      throw new Error(`Config field "${path.join(".")}" is not volatile`);
    }
  }
  ```
  DSH 0.2.1 规定：所有在设置面板中被用户编辑并提交持久化的字段，必须在 Schema 中声明为 `.volatile()`。任何非 volatile 字段进入 `settings.mutate()` 或 `settings.update()` 均会被抛出 `Config field "<name>" is not volatile` 异常并阻断写入事务。
- 参考工程基线（`dsh-qqbot-bridge/src/config/schema.ts`）中，核心身份与秘钥（`app_id`、`app_secret`）全部标记为 `.volatile()`。
- 本项目前期修改中，误判将 `bot_qq` 留为非 volatile，并在契约测试中固化了该错误断言。

### 1.2 服务端路由静默吞错
前端卡片在点击“保存”时，会将包含 `bot_qq` 的全部 25 个字段作为 draft 发送 `POST /plugins/dsh-napcat-bridge/config`。
服务端 `src/server/routes.ts` 收到 payload 并调用 `settings.mutate(SETTINGS_NAMESPACE, ops)` 时触发上述异常，但在原代码中被：
```typescript
} catch {
  // ignore persistence errors in test/mock environments
}
```
静默吞掉，并向客户端返回了假成功响应 `200 { ok: true }`。这导致磁盘 profile 从未被写入，且没有任何错误日志暴露。

### 1.3 前端面板重新挂载打回原形
用户关闭设置面板时，卡片组件被卸载（unmount）。当再次打开设置面板时，组件重新挂载（mount）并通过 `loadRemoteConfig()` 发送 `GET /plugins/dsh-napcat-bridge/config`。服务端从 `settings` 服务读取，因磁盘上从未写入过修改，返回的依然是初始默认值，导致表单全量变回默认配置。

### 1.4 配置合并优先级颠倒
`src/index.ts` 中的 `currentConfig()` 原为 `mergeConfigs(fromSettings, fromArgs)`，以 `fromSettings` 为底、以 `fromArgs`（启动参数）为覆盖，导致外部启动参数中的默认值会反向压制 settings 配置中的改动。

---

## 2. 修复实施

| 修改文件 | 修改内容 |
|---|---|
| `src/config/schema.ts` | 为 `bot_qq` 补齐链式 `.volatile()` 声明，使全部 25 项配置均具备 DSH 易失性支持 |
| `src/server/routes.ts` | 规范错误处理：去除静默吞错，持久化失败时记录 `logger.error` 并返回 HTTP 500 与错误详情 |
| `src/index.ts` | 调整配置合并优先级为 `mergeConfigs(fromArgs, fromSettings)`，确保 UI 设置拥有最高优先级覆盖权 |
| `tests/contract/settings-schema-alignment.test.ts` | 契约测试更新：断言全量 25 项配置均标记为 `.volatile()`（包含 `bot_qq`） |
| `tests/contract/server-routes.test.ts` | 增加契约测试：断言持久化异常时返回 500 与日志、断言保存包含 `bot_qq` 的全量配置后后续 GET 能正确读取保存值 |
| `dist/*` | 执行 `pnpm build` 同步编译产物，确保真机与 link 部署装配路径生效 |
