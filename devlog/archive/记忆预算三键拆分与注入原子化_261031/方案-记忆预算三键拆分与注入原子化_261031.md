# 方案：记忆预算三键拆分与注入原子化（261031）

## 1. 背景与目标

现有记忆预算由两个配置键承担多重语义：

- `group_memory_budget_chars`：群聊 Session 规则写入上限 + 群聊注入总预算。
- `private_memory_budget_chars`：用户画像写入上限 + 私聊 Session 规则写入上限 + 私聊注入总预算。

这导致“允许写入的内容”和“实际可注入的内容”互相矛盾，并在注入侧产生 Session 规则切片、私聊画像切片等非原子行为。

本轮目标：

1. 将预算配置拆为三个语义单一的键。
2. 写入侧保持“超预算拒绝且不落盘”，只调整 limit 来源与报错文案。
3. 注入侧保持文件内容原子：Session 规则与私聊画像全量注入；群聊画像按用户画像总预算整块装填，放完当前块后下一个不注入。
4. 旧配置键通过运行时清洗与 profile 文件自愈自动迁移。

## 2. 配置契约

| 键 | 语义 | 默认值 |
|---|---|---|
| `user_profile_budget_chars` | 单个用户画像文件的写入上限 | 2200 |
| `session_memory_budget_chars` | 单个 Session 规则文件的写入上限 | 2200 |
| `group_memory_total_budget_chars` | 群聊注入时所有活跃用户画像合计的总预算；Session 规则不计入 | 8000 |

旧键迁移：

- `memory_budget_chars` → `group_memory_total_budget_chars`
- `group_memory_budget_chars` → `group_memory_total_budget_chars`
- `private_memory_budget_chars` → `user_profile_budget_chars`

迁移入口统一由 `src/config/legacy.ts` 提供；`sanitizeConfigPayload`、`readLegacyConfig`、`healProfileConfigFile` 共用。

## 3. 写入侧

- `create_memory`：内容长度超过对应上限时返回失败，**不写入文件**。文案明确“本次创建未写入”，并引导模型精简后重新创建，或先创建简短基础内容再增量补充。
- `edit_memory`：编辑后总长度超过对应上限时返回失败，**不写入文件**。文案明确“本次编辑未落盘”，并给出当前长度、上限与还需缩减的字符数。

## 4. 注入侧

- Session 规则：全量注入，永不切片。
- 私聊用户画像：全量注入，永不切片。
- 群聊用户画像：按 `group_memory_total_budget_chars` 装填；每份画像整块注入；放完当前块后达到/超过总预算时，后续用户不再注入，并保留现有截断提示。
- 保留 7 天活跃筛选与“当前发言人优先”排序。

## 6. 实施结果（261031）

- 配置侧：新增 `src/config/legacy.ts` 作为旧键迁移单一真相源；`sanitizeConfigPayload`、`readLegacyConfig`、`healProfileConfigFile` 全部接入。物理自愈会将 profile patch 中的旧键原地重命名并保留旧值，同时避免多代旧键产生重复新键。
- 写入侧：`create_memory` / `edit_memory` 超预算继续拒绝且不落盘；`user` 使用 `user_profile_budget_chars`，`session` 使用 `session_memory_budget_chars`，报错文案明确“本次创建未写入 / 本次编辑未落盘”并给出需缩减字符数。
- 注入侧：删除 Session 规则与私聊画像的切片；群聊预算只统计用户画像，整块装填，放完当前画像后达到/超过预算则停止后续并保留截断提示。
- 设置面板：记忆 Tab 更新为 `memory_storage_dir` + 三个预算键，共 4 项；Schema / 服务端默认值 / 客户端默认值统一为 30 键。
- 验证结果：`pnpm typecheck` 通过；相关 7 个契约测试文件 62/62 通过；全量 `pnpm test:quick` 77 个文件、621 passed / 3 skipped；`pnpm build` 成功，`dist/` 已包含新键、新报错文案，旧键仅存在于 `dist/config/legacy.js` 迁移表中。
