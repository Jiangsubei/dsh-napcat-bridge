## 1. 交付目标与背景

1. **消除冗余流水账与寒蝉效应**：原工具定义中充斥大量“切勿”、“严禁骚扰”等恐吓性词汇，以及冗长的传参说明，造成大模型过度克制或 Token 严重浪费；
2. **入参统一规范**：历史代码中混杂了 `user_id` 与 `target_user_id`，存在向下兼容胶水代码；
3. **参数精简优化**：移除了 `send_file` 中无用的 `file_type`、砍掉了 `list_faces` 中多余的 `cursor` 游标；
4. **工具职责纯净化与解耦**：
   - `collect_face` 纯粹只做“收录入库”（从指定消息或最新图收藏），不再混杂“传 face_id 变成补标/改标”的模式重载；
   - 独立研发 `manage_faces` 工具专职负责表情库治理（补充/修改标签、按 ID 删除表情、查询配额占用、淘汰冷门表情）。

---

## 2. 核心交付成果

### 2.1 工具定义设计铁律（Tool Definition Specification v2）落地
- **分级模式**：简单工具一句话自然融入 When；复杂/易混淆工具分句写明核心功能与 When to use；
- **参数自解释**：描述聚焦 Why & When，参数 schema 表达 How to use，移除教大模型调接口的冗余废话；
- **极致精炼**：精炼中英文描述，大幅压降每回合常驻 System Context 的 Token 预算开销；
- **排他原则防混淆**：仅在易混淆边界使用中性 `not for...` 阻断错误路由；
- **代码运行时拦截**：以明确的代码报错引导重试，替代提示词恐吓；
- **统一入参命名**：全量统一为 `user_id`（目标用户的 QQ 号），不留任何多余兼容代码。

### 2.2 独立表情管理工具 (`manage_faces`) 研发与装配
- **支持动作**：
  1. `update_tags`：修改指定 `face_id` 的表情标签 (`tags`) 与情绪 (`mood`)；
  2. `delete`：按 `face_id` 删除表情；
  3. `query_quota`：查询当前表情库存储配额占用与总容量；
  4. `evict`：按配额或指定数量淘汰最久未用的表情。
- **纯化 `collect_face`**：仅保留 `message_id`、`tags`、`mood` 参数，纯粹负责将消息中的图片收录入库。
