# 任务包：四个斜杠命令 (/stop /new /resume /ctx)

> **项目**: dsh-napcat-bridge  
> **日期**: 2026-09-05  
> **优先级**: P1  
> **相关架构**: `src/commands/index.ts`（命令分发）、`src/gateway/session.ts`（SessionManager）

---

## 1. 背景

现有斜杠命令：`/mode` `/model` `/think` `/clear` `/help`，均走管理员白名单门控（`handleSlashCommand` 内 `isAdmin` 检查）。

本任务新增 `/stop`、`/new`、`/resume`、`/ctx` 四个命令。

## 2. 需求

| 命令 | 语义 |
|---|---|
| `/stop` | 停止当前会话正在进行的生成（对齐 DSH WebUI 停止按钮） |
| `/new` | 原 `/clear` 改名（开启新会话，版本号+1），保留 `/clear` 为别名 |
| `/resume` | **切换会话**：列出 peer 所有历史会话，按序号恢复某个被 /clear 掉的旧会话 |
| `/ctx` | 显示当前会话上下文用量（对齐 WebUI 的「上下文已用 25% ~250K/1M」） |
| `/help` | 更新命令清单 |

**全部命令保持现有管理员白名单门控。**

## 3. 详细设计

### 3.1 `/stop` — dsh-commands/index.ts

```ts
case 'stop': {
  const sessionController = context.ctx.get('sessionController') || (context.ctx as any).sessionController;
  if (!sessionController?.cancel) {
    return { handled: true, success: false, error: 'sessionController 服务不可用' };
  }
  try {
    const result = await sessionController.cancel({ sessionId: context.session.id });
    return { handled: true, success: true, reply: '⏹️ 已停止当前生成。' };
  } catch (err: any) {
    return { handled: true, success: false, error: `停止失败: ${err?.message || String(err)}` };
  }
}
```

> ⚠️ 实现前先到 DSH 源码 `dsh-api-session-controller` 确认 `sessionController.cancel` 的确切签名（可能是 `cancel({ sessionId })` 或无参、或需通过 `remote.session.cancel`）。以 `.local/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/dsh-api-session-controller/lib/client.js` 的 `cancel()` 封装为准（line ~991，内部调 `remote.session.cancel({ sessionId })`）。

### 3.2 `/new` — 重命名 /clear

- `case 'new':` 复用现有 `case 'clear'` 逻辑（`markSessionCleared`）
- `case 'clear':` 保留，转发到同一逻辑（别名）
- `/help` 展示为 `/new (clear)`

### 3.3 `/resume` — 切换会话

**前置**：在 `SessionManager`（`src/gateway/session.ts`）新增两个方法：

```ts
/**
 * 列出 peer 的所有历史会话（来自 wsRegistry.headers，parseSessionId 匹配同 base）
 * 按 (round, version) 升序返回（旧→新）
 */
listPeerSessionIds(peer: string): string[]

/**
 * 切换 peer 当前活跃会话到指定 sid
 * 前置校验：物理存在 且 未归档；通过则写 peerCurrentSessionId + clearedVersions + db
 */
resumeSession(peer: string, sessionId: string): boolean
```

要点：
- `listPeerSessionIds` 复用 `parseSessionId` 匹配 base（同 `peerToSessionId` 里 `wsRegistry.headers` 扫描逻辑），过滤 `isSessionPhysicallyPresent`
- `resumeSession`：`peerCurrentSessionId.set(peer, sessionId)` + `clearedVersions.set(peer, {round, version})`（从 parseSessionId 取）+ 存 db。`peerToSessionId` 已有缓存优先，会自动路由到该会话

**命令逻辑**（`/resume` 无参 = 列列表，有参 = 恢复）：

```ts
case 'resume': {
  const sm = context.sessionManager;
  const peer = sm!.sessionIdToPeer(context.session.id);
  if (!args) {
    const sessions = sm!.listPeerSessionIds(peer);   // 升序：旧→新
    // 渲染：最新在最上面（编号 N），最旧的编号 1 在最下面
    const lines = [...sessions].reverse().map((sid, i) => `${sessions.length - i}. ${sid}`);
    return { handled: true, success: true, reply: `📂 ${peer} 的会话：\n${lines.join('\n')}\n\n用法: /resume <序号>` };
  }
  const idx = parseInt(args, 10);
  const sessions = sm!.listPeerSessionIds(peer);
  const target = sessions[idx - 1];   // 1=最旧 → sessions[0]
  if (!target) return { handled: true, success: false, error: `序号无效，范围 1~${sessions.length}` };
  const ok = sm!.resumeSession(peer, target);
  return ok
    ? { handled: true, success: true, reply: `✅ 已切换到会话 ${target}` }
    : { handled: true, success: false, error: '恢复失败：会话不存在或已归档' };
}
```

> 注意：`resumeSession` 接受的是**序号对应会话**，`idx-1` 定位升序数组。最新会话序号 = sessions.length（最大）。

### 3.4 `/ctx` — 上下文用量

```ts
case 'ctx': {
  const tokenMeter = context.ctx.get('tokenMeter') || (context.ctx as any).tokenMeter;
  if (!tokenMeter?.measure) return { handled: true, success: false, error: 'tokenMeter 服务不可用' };
  const usage = tokenMeter.measure(context.session);   // { totalTokens, surfaceTokens, nodes, baseline }
  // 上下文上限：模型 contextWindow（llm discover 或 session model 元数据）
  // 拿不到就不显示百分比，只显示 totalTokens
  ...
}
```

要点：
- `measure(session)` 返回 `{ totalTokens, surfaceTokens, baseline, nodes }`
- 用 `nodes` 分段（系统提示词/工具/对话），与 WebUI 对齐
- 上限 `contextWindow` 从当前会话所用模型的元数据拿；**拿不到就直接只显示 totalTokens，不显示百分比/上限**（这是 DSH 的事，它一般会给默认值）
- 输出示例：
  ```
  🧠 上下文已用 ~250K
        
  ~250K / 1M (25%)
  系统提示词 ~1.7K
  工具 ~17K
  对话消息 ~113K
  ```

> ⚠️ 实现前确认：`measure` 是否需要 `requestHeader` 才准确（源码注释：无 requestHeader 用 `state.header` 估算）。若当前只传 session 也可，优先简单实现；必要时从 session 的模型选择构造 requestHeader。上限来源以 `dsh-token-meter` + `dsh-llm` 的 `contextWindow` 为准（`/model` 已有的 `getDiscoveredModels` 或 model 元数据）。
