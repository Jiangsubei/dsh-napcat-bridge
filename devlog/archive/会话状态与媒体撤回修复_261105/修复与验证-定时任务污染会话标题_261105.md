# 修复与验证：定时任务污染私聊会话标题

> 日期：2026-11-05　状态：已实现并通过契约测试与构建（待真机验收）

## 1. 问题现象

某个私聊会话被触发过一次定时任务后，会话标题从真实好友昵称
（如「私聊: 小明 1000000001 #1」）变成「私聊: 系统定时任务 1000000001 #1」，
且重启后仍然保留，相当于昵称被永久改掉。

## 2. 根因

旧版 `SessionAgentRunner.dispatchWakeup` 更新私聊标题的判断是：

```ts
if (payload.from_name && payload.trigger !== 'internal_agent') {
  if (payload.peer.startsWith('user_') || payload.peer.startsWith('qq-user-')) {
    this.updateSessionTitle(session, peer, sessionId, payload.from_name);
  }
}
```

只排除了 `internal_agent` 一种系统触发器：

- 定时任务 payload 由 `src/scheduler/index.ts` 构造：
  `trigger: 'scheduled'`、`from_name: '系统定时任务'`；
- 该 `from_name` 被当作真实好友昵称传给 `updateSessionTitle`；
- `updateSessionTitle` 内部还会 `setPeerName()`，把「系统定时任务」写入
  `plugin_kv:napcat_peer_names`；
- 之后即使真实消息到达前，`ensurePeerName` 也会优先命中这份错误缓存，导致标题长期不回退。

之前“名字未知时不得降级覆盖”的修复只防住了 **没有名字** 的情况，
防不住这种 **带着错误名字** 的系统唤醒。

## 3. 变更

### 3.1 标题更新改为「真实发送者白名单」

`src/gateway/session/agent-runner.ts`：

```ts
const REAL_SENDER_TRIGGERS = new Set(['at', 'mention', 'quote', 'poke']);
```

只允许以下触发源的 `from_name` 更新私聊标题：

- `at`（私聊普通消息生产链路即使用该值）
- `mention` / `quote`（群聊消息，标题更新仍限定 user peer）
- `poke`（戳一戳）
- `private`（历史/兼容标识，语义同为真实私聊发送者）

`scheduled` / `proactive` / `internal_agent` 等系统触发器一律不再改写标题。

### 3.2 历史污染清理与自愈

- `loadPeerNames()`：加载 `plugin_kv:napcat_peer_names` 时，私聊 peer 的
  「系统定时任务 / 协同 Agent / 系统协作总线 / 内部通讯」等系统身份名称直接丢弃，
  并回写清理结果（群名不受影响，群可能真的叫这个名字）；
- `updateSessionTitle()`：若已有私聊标题中提取出的名称是系统身份，视为“无有效昵称”，
  允许把标题自愈为中性号码标题（下一次真实消息会补回正确昵称）；
- `getSessionDisplayName()`：展示层同样过滤系统身份名称，避免行为兜底再次泄露。

## 4. 测试

新增 `tests/contract/scheduled-title-guard.test.ts`：

1. `trigger='scheduled'` + `from_name='系统定时任务'` → 不调用 rename、标题不变、昵称缓存为空；
2. `proactive` / `internal_agent` → 同样不改写标题；
3. 真实私聊消息 `trigger='at'` + `from_name='小明'` → 正常更新为「私聊: 小明 …」；
4. 历史污染清理：`plugin_kv` 中的私聊「系统定时任务」被丢弃并回写数据库，
   已污染标题自愈为「私聊: <QQ号> #1」；同名群名保留。

## 6. 行为说明

- 若真实好友的 QQ 昵称本身就叫「系统定时任务」，升级后该昵称会被当成污染丢弃一次，
  但后续 `ensurePeerName` / 真实消息会从 QQ 资料重新解析并恢复；
- 历史已被改名的会话不需要手工处理：重启插件后缓存被清理，下一次标题刷新即自愈。
