# 修复与验证：出站媒体、撤回保留、历史默认过滤、会话昵称与 IPC 回执约束

> 日期：2026-11-05　状态：已实现并通过全量契约测试（待真机验收）

## 1. 出站媒体元数据补全

### 问题

出站自记录只保存发送 payload：`file_id/local_path/fingerprint` 全为 null。
图片/文件在历史里只剩 `file:///...` 文本，`has_file` 不命中，跨会话转发需要从内容里抠路径。

### 实现

- `src/outbound/self-record.ts`
  - `extractOutboundMediaMeta`：从 payload 解析
    - `local_path`：仅接受 `file://` URI 与本地绝对路径（URL/base64 不落本地路径）；
    - `file_id`：文件段优先 `data.file_id`；图片等仅当 `data.file` 像媒体标识（非路径/URL）时采用；
  - `enrichOutboundMediaRecord`：含媒体段时异步 `get_msg(message_id)`（5s 超时）回填
    `file_id`、`busid`、`raw`；**payload 解析出的 `local_path` 优先保留**，回查失败只记 debug。
- `src/gateway/server.ts`：`getMsg(messageId, timeoutMs = 15000)` 支持超时参数。
- `src/storage/database.ts`：新增 `updateMessageMedia(msgId, patch)`，仅更新传入字段。
- `src/index.ts`：`onMessageSent` 落库后触发异步补全（不阻塞发送返回）。

### 证据

- SnowLuma `index.mjs`：`send_group_msg` 仅返回 `{message_id}`；`get_msg` 返回完整消息对象
  （并刷新媒体 URL）。
- 真实历史库：入站文件段含 `file_id/file_size/local_path`；图片段含 `file/url/local_path`。

### 验证

`tests/contract/outbound-self-record.test.ts` 新增：
- payload `file://`/绝对路径 → `local_path` 正确；URL/base64 → null；
- 图片出站后 `get_msg` 回填补全 `file_id` 与 `raw`，且保留 payload 的 `local_path`；
- `get_msg` 失败 → payload 版本保留，不丢记录。

## 2. 撤回内容保留策略

- `markRecalled` 改为：`self=1` 仅置 `recalled=1` 保留原文；`self=0` 才替换为 `〔已撤回〕`。
- `recall_message` 工具撤回成功后立即调用 `db.markRecalled`，不再依赖 NapCat 自身撤回 notice。
- 测试：`tests/contract/recall-self-content.test.ts`（自身保留、他人占位、工具即时标记）。

## 3. 历史查询默认隐藏内部通讯

- `readChatHistory` 缺省补 `source='qq'`；显式 `source='agent'` 才看内部通讯；
  `source='all'` 表示两者都要（DB 层忽略未知值）。
- 工具 schema `source: 'qq' | 'agent' | 'all'`，返回摘要仍带 `source`。
- 测试：`internal-message-record.test.ts` 契约 12（默认 / agent / all）。

## 4. 会话昵称：持久化、懒解析、禁止降级

### 根因

- `peerNames` 仅内存，重启即丢；
- `getOrCreateAgent` 无条件 rename，名字未知时把「群聊: 名称 123 #1」覆盖成「群聊: 123 #1」；
- 内部主动创建的会话（`create_user_agent` / `send_agent_message`）没有昵称来源。

### 实现

- `agent-runner.ts`
  - `peerNames` 持久化到 `plugin_kv:napcat_peer_names`，构造时恢复；
  - `resolvePeerName`：缺失时通过 `get_group_info`（`group_name`/`group_remark`）或
    `get_stranger_info`（`nickname`/`remark`）解析，3s 超时；
  - `updateSessionTitle`：现有标题可反向提取名称；名字未知且已有标题时**直接跳过 rename**，
    绝不降级；现有标题通过 `sessionTitle.get(session)` 读取。
- `session.ts`：暴露 `ensurePeerName`；`getSessionDisplayName` 优先从活动会话标题反向取名称。
- `agent-ipc.ts`：`create_user_agent` / `send_agent_message` 在建会话前 `ensurePeerName`，
  首建标题即带昵称。
- `id-resolver.ts`：新增 `extractNameFromSessionTitle`。
- 测试：`tests/contract/session-title-name.test.ts`（解析边界、真实装配查询与 plugin_kv 持久化、
  不降级覆盖）。

## 5. 内部协作「回执即止」

- `QQ_PRESET_PERSONA_PREFIX`、`formatWakeupPrompt(internal_agent)`、
  `send_agent_message` / `create_user_agent` 描述统一加入：
  被派发方回执一次即止；发起方收到回执后，用户无新要求不再回复确认/致谢/追问。
- 测试：`tests/contract/ipc-reply-loop.test.ts`。
