## 2. 核心技术实施说明

### 2.1 Waterfall 先手注册（A4 / A5）
- DSH 0.2.1 的 `approval/request` 与 `user-questions/request` 均由 Cordis `waterfall` 事件总线驱动，按监听器链依次执行，先认领者（不调用 `next()`）即 veto 后续处理者；
- 若宿主 WebUI Answerer 默认注册且不判定 QQ 会话，插件后置注册将被截胡；
- 在 `src/index.ts` 与 `src/approval/responder.ts` 中均显式指定 `{ prepend: true }`（底层由 Cordis 使用 `unshift` 置于队首），实现 QQ 会话优先命中，非 QQ 会话通过 `next()` 流转宿主。

### 2.2 0.2.1 就绪与销毁生命周期（A6）
- **就绪机制**：通过 `ctx.get('appReady')` 的 `onReady(listener)` 注册系统就绪钩子，提交就绪后再执行 `migrateLegacyConfig`；对于独立测试等无 `appReady` 的场景，提供直接执行兜底；
- **销毁机制**：通过 `ctx.effect(() => () => { void disposePlugin(); })` 绑定到 Cordis Fiber 的标准生命周期，当插件或 Context 被 `dispose()` 时，Disposer 必然触发，注销 REST 路由、移除 `process.on('SIGINT'/'SIGTERM')` 监听、关闭 SQLite 数据库连接；
- **Cordis 服务访问防护**：清理了历史遗留的 `ctx.get('x') || (ctx as any).x` 模式，避免未注入服务时触发 Cordis 代理的 `cannot get property "..." without inject` 异常。

### 2.3 REST 路由生命周期与重复注册容错（A11）
- `registerConfigRoute` 生成的清理逻辑不仅返回给调用者，同时注册到 `ctx.effect`；
- 当 `webServer.register` 检测到路由冲突抛出 `webserver: duplicate exact route` 异常时，通过内部 `try...catch` 降级记录警告日志，不再中断插件加载流程。
