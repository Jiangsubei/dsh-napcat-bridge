## 三、0.2.1 变更要点（来自 `docs/调研纪要-DeepSeek_Harness_0.2.1升级与项目适配深度分析.md`，需对照真实 0.2.x 包复核）

1. 子路径插件（`<pkg>/client`）不再读取独立 package.json；locale 需 `<subpath>/locale/{en,zh}.json`（内嵌 `meta`），icon 需 `<subpath>/icon` 导出（≤256 KiB）。
2. 新增 `engines.dsh` 兼容性前置检测。
3. 移除各包 `./invariant` 导出。
4. 新增插件会话记录接口 `appendPluginRecord` / `pluginRecordOf`（可选增强）。
5. 设置系统从 `settings.yaml` 迁移到 Profile Patch（`cordis.patch.yml`）；服务端删除 `ctx.settings.installSection()`；客户端沙箱删除 `settingsScope`；Schemastery 提供 `.volatile()` 与 `.role('secret')`。
6. 设置弹窗改为左侧导航独立页（`settings.section` 插槽）；`settings.plugin.item` 废弃。
7. Primitives 图标删除定尺寸后缀（`IconChevronDownOutline14` → `IconChevronDownOutlineRegular/Medium`）。
8. `conversation.composer.stats` 拆为 `activity` / `usage`，新增 `conversation.input.model.label`。
9. Desktop 与 Web 统一由 `@deepseek-ai/dsh-client-modules` 扫描，要求相同 lazy-CJS 模块工厂规范。

## 六、判定口径

- **A 半截更新**：代码/配置里同时存在 0.1.5 与 0.2.x 两套观念、或已按 0.2.x 改了声明却没改实现/依赖/产物/测试；典型：版本声明与 devDeps 不一致、旧插槽名残留、旧 API 调用未删净、文档宣称完成但代码未落地、`dist/` 与 `src/` 不一致。
- **B 技术债**：能跑但结构/契约/错误处理/类型安全/性能存在隐患；例如 `any` 泛滥、重复实现、魔法字符串、缺少清理逻辑、测试替身替代真实装配、注释与实现不符。
- **C 死代码**：全仓无引用（含导出、测试、脚本、动态字符串拼接）、恒假分支、不可达、废弃文件、被新实现取代但未删除的旧实现、未使用依赖/资源。
- **严重级别**：P0=会导致 0.2.1 下功能不可用/崩溃；P1=规范不符或显著隐患；P2=清洁度问题。
