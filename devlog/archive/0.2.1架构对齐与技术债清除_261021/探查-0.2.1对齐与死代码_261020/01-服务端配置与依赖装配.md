## 4. 待确认项（无法在本仓库确证）

1. **`dsh.client.inject` 是否必须包含 `@deepseek-ai/dsh-client-connection` / `@deepseek-ai/dsh-client-ui-settings`**：参考工程声明了（`dsh-qqbot-bridge/package.json:30-35`），但两者都是"package-name 边、非服务注入"（`dsh-package-manifest/types.d.ts:79-80`）。本仓库客户端未 require 它们，且 `tests/contract/client-settings.test.ts:147` **显式断言不得包含** `@deepseek-ai/dsh-client-connection`。该断言是"旧写法禁止"还是"误判"无法在服务端侧确证 → 须由客户端代理/真机确认。
2. **`@deepseek-ai/dsh-client-ui-primitives` 是否在模块表基线（staticModules seed）中**：本仓库 bundle 直接 `require` 它（`dist/client.js`）却未列入 `dsh.client.inject`。若它不是 seed 而是 graph row，则存在 factory 到达顺序风险。尝试在 `dsh-web-frontend` 产物中定位 `staticModules:{...}` 未成功 → 待确认。
3. **`ctx.on('ready')` / `ctx.on('dispose')` 是否被 DSH 其它包通过 `declare module` 补声明并在运行时真的 emit**：已确认 cordis 4.0.4 无此二事件、`dsh-app-boot`/`dsh-base`/`dsh-settings` 均无 `emit('ready')`/`emit('dispose')`。但参考工程 `dsh-qqbot-bridge/src/index.ts:753,782` 使用同一写法，**无法排除**某处 emit 未被本次 grep 覆盖（本次 grep 排除了 client/web 产物）→ 建议真机打点确认后再动手改 A5。
4. **`settings.configure({ auto: false }, ctx.fiber)` 在 `ctx.inject` 子 fiber 内、显式传父 fiber 是否合法**：0.2.0-rc.2 签名存在（`dsh-settings/lib/types/index.d.ts:80-82`：「@throws If this instance already has a registered policy」），但"同一实例重复注册"的边界（插件重挂时 `auto` 策略是否残留）需真机验证。
5. **`settings` 服务在 headless（无 `profileContext`）时缺席的影响面**：base patch 中 `settings` 行 `disabled: !!js "!ctx.get('profileContext')"`（`dsh-base/cordis.patch.yml:101-102`），此时 `ctx.get('settings')` 为 undefined，routes 的持久化分支整体跳过，仅内存 reconcile 生效 → 需确认这是否为预期（配置无法持久化）。

## 5. 结论摘要（按优先级排序）

1. **P0** peerDependencies 的 `^0.2.0` **无任何已发布版本可满足**（`npm view @deepseek-ai/dsh-base@^0.2.0` → E404，registry 只有 `0.2.x-rc/alpha`）→ 用户安装即解析失败。真正该改的是**版本范围**（`^0.2.1-rc.2`），而非包名——「幽灵包」假设不成立（A1）。
2. **P0** `devDependencies` 仍 `0.1.5-rc.1`（`package.json:86-117` + `pnpm-lock.yaml:25-74` + `node_modules` 实测），「从未在 0.2.x 类型下编译验证」成立；`tsc --noEmit` EXIT=0 只能证明 0.1.5 下通过（A2）。
3. **P0** `src/boot.ts:16` 导入的 `healProfilesModuleFallback` 在 0.2.0-rc.2 **已被删除**（`dsh-app-boot` 0.2 `index.d.ts:37` 导出清单无、`lib/index.js` grep `heal` 零命中）→ 升级 devDeps 后必然编译失败；`dist/boot.js:11` 同样带着这个不存在的导入（A3）。
4. **P0** `ctx.on('ready')` / `ctx.on('dispose')` 在 cordis 4 **不是真实事件**（`events.d.ts:216-244` 只有 `internal/*`，拆除只发 `internal/plugin`，`lib/index.js:969-984`）→ **旧配置迁移永不执行**、**插件 dispose 清理整体失效**（`db.close`/`server.stop`/定时器/工具反注册/路由反注册）（A5、C3）。
5. **P1** 叠加 A5：`src/server/routes.ts` 注册的 `/plugins/dsh-napcat-bridge/config` 不会被反注册，而 `WebServer.register` 对重复 `(kind,path)` **直接抛错**（`dsh-host-webserver/lib/index.js:179`）→ 插件重挂后路由注册失败、旧闭包继续服务（B4）。
6. **P1** 设置热更新链路是空转：schema 全仓无 `.volatile()`，而 `loader/volatile-update` 只对 volatile 字段按 fiber 过滤触发（`cordis-plugin-loader/lib/index.js:420`）→ `src/index.ts:208-212` 永不触发；同时 0.2.x 普通配置变更会整体重挂插件，reconcile 状态机价值存疑（A6）。
7. **P1** `settings.get(ns)` 是 0.1.5 API，0.2.x 的 `SettingsForms` **没有 `get`**（`dsh-settings` 0.2 `index.d.ts:62-117`）→ `migrate.ts:121` 的「profile 已有配置则跳过」守卫失效（`index.ts:69` 尚有 `describe()` 兜底）（A7）。
8. **P1** `settings.mutate(ops)` 单参回退在**两个版本都不存在该签名**（`routes.ts:153`、`migrate.ts:177`）→ 恒抛错，属死分支（A8）。
9. **P1** 0.2.x 的 `dsh-settings` **已内建 settings.yaml → profile 导入**（`lib/index.js:343-362`）→ 本仓库 `src/config/migrate.ts` 187 行自研迁移整体冗余，且因 A5 根本不会跑（A9）。
10. **P1** `src/server/routes.ts` 的 REST 契约是**自造**：官方 host 包无 `/plugins/*` 路径先例（grep 官方包 `path: "/plugins` → 0 命中），且 POST 路由**无鉴权/无来源校验/无体积上限/无 schema 校验**（B1-B3）。
11. **P1** `src/index.ts:157` 把 `ws_token` 明文打进日志（字段本身标了 `.role('secret')`，`schema.ts:31`）（B5）。
12. **P1** 死依赖/幽灵依赖：`zod` 从未 import（C1）；`js-yaml`/`yaml` 从本包根**不可解析**，`parseYaml` 的第 2/3 级兜底不可达（C2）。
