## 5. 结论摘要（按优先级排序）

1. **A1/A2（P0）**：`approval/request`（`index.ts:446`）与 `user-questions/request`（`responder.ts:337`）注册时都缺 `{ prepend: true }`。cordis 默认 `push`（4.0.4 `lib/index.js:336`），Web+QQ 同部署时宿主 answerer 先 claim，**QQ 侧审批/提问卡片根本不会被处理**——与参考工程 2026-09-15 真机缺陷同因。这是本模块唯一会让 0.2.1 下功能整体不可用的问题。
2. **A3/A4/A5/A6（P1）**：审批链路「无超时 + 同 peer 静默顶替 + abort 记成 rejected + 缺 peer 也记成 rejected」四连，导致 agent 可被永久挂起、并发审批丢请求、审计结论被污染。0.2.x 已给出 `callId`（`types.d.ts:61`）与四值 `ApprovalOutcome`（`:26`），当前实现两样都没用上。
3. **A7/B11（P1）**：提问链路同构缺超时/顶替；且审批只按 `peer` 命中，**群里任何人回 `y` 即放行工具执行**（提问路径至少要求引用卡片）。后者属产品安全口径，需用户拍板。
4. **A9（P1）**：`session.ts` 多处直接读写 0.2.x `WorkspaceRegistry` 的 `private` 字段（`headers`/`sessionPaths`/`invalidSessionPaths`）并 `delete` 宿主内部索引，且 `@deepseek-ai/dsh-workspace` 未在任何 dependencies 中声明。运行时因字段未用 `#` 而侥幸可用，**一次上游重构即静默失效**（三处 `try/catch{}` 吞错）。
5. **A8/A10（P1）**：自造 `RemoteError` 的 code 不在 0.2.x `RemoteErrorDetailsMap` 内；`sessionController` 服务在两版 `.d.ts` 中均不存在却被猴补丁改写 `prompt`。两者都是「按 0.1.x 经验猜 API」的产物。
6. **A15（P2→放大为结构性风险）**：devDeps 仍为 `0.1.5-rc.1`（`package.json:88-104`），配合本模块 47/21/22 处 `as any`，**0.2.x 类型从未参与编译**；`typecheck` 的绿色对 0.2.1 不具备证明力。
7. **B1/B2（P1）**：`server.ts` 对 async handler 的 `try/catch` 实际无效（未处理 rejection 可崩进程）；`media.ts` 用 LLM 传入的 `filename` 直接 `path.join` 落盘，存在路径穿越（净化函数只存在于 `private-file.ts`）。
8. **B10/B14（P1）**：出站 `turn/start` 只绑定第一条 pending（`break`）导致多消息场景上下文串轮；`shouldWakeup` 两处调用未传 `bot_nickname`，昵称唤醒在生产路径从未接线。
9. **C 类 12 项**：`createMemberNicknameResolver`、`DownloadResourceOptions`、`getHumanMessageTime`、`setDatabase`、`getDshHome`、`onMeta`(+整个 meta_event 空转分支)、`getStrangerInfo`、`isSessionPhysicallyPresentAsync`、`uploadGroupFile`/`uploadPrivateFile`、`memberResolver.clear()`、恒等三元 `round > 0 ? 1 : 1`、重复的引用格式化块——全部有全仓 grep 计数为证（1 命中或仅测试命中）。
10. **测试可信度**：本模块核心装配测试质量其实不错（`storage-query` 用真实 better-sqlite3、`question-interception` 用真实 WS + 真实 `userQuestions.ask`、`session-serial-queue` 用真实 `agents.create`），但 `questions-provider-channel.test.ts` 的协作式宿主 mock（A14）与全量并发下的随机超时（B15）会同时制造**假绿**与**假红**，须与 A1/A2 整改一并处理。
