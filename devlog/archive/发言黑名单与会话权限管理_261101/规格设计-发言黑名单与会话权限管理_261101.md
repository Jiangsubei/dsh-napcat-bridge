## 1. 需求背景与核心目标

随着 dsh-napcat-bridge 在群聊和私聊场景的深入使用，对机器人的运行安全、会话权限隔离以及 Token 消耗管理提出了更高的精细化控制诉求：
1. **防止误唤醒与骚扰**：需要针对特定恶意 QQ 用户或特定群聊设置黑名单；进入黑名单的会话消息正常入库审计，但一律不唤醒机器人、不回复、不执行指令，且即使是管理员也不例外；
2. **会话默认权限隔离（DSH 规范）**：防止群聊普通成员借由机器人越权修改工作区代码；群聊新建会话默认置为只读（`read-only`），私聊默认开放工作区读写（`workspace-write`），同时支持为特定群或用户配置例外权限；
3. **Coding 工具组按需裁剪**：针对纯闲聊或答疑场景的群聊/私聊，支持关闭工程编码工具（`bash`, `pwsh`, `read`, `write`, `edit`, `read_image`, `working_directory`），利用 DSH 原生 `tools.restrict` 硬隔离，防范提示词越狱注入并大幅降低上下文 Token 消耗。

## 2. 核心架构与功能规划（方案 A：分区架构）

在 Web UI 设置面板新增独立 Tab：**`security`（标签：安全与权限）**，内部划分为三个逻辑分区：

```
┌─────────────────────────────────────────────────────────────┐
│ Web UI 设置卡片: [权限与安全] (id: security)                 │
├─────────────────────────────────────────────────────────────┤
│ 1. 发言黑名单 (Message Blacklist)                           │
│    - 私聊黑名单 (private_blacklist): [QQ号 + 备注] 列表     │
│    - 群聊黑名单 (group_blacklist): [群号 + 备注] 列表       │
│    * 铁律: 消息入库落盘, 永不唤醒, 管理员亦不豁免            │
├─────────────────────────────────────────────────────────────┤
│ 2. 新建会话权限模式 (Session Permission Preset)             │
│    - 私聊新建默认权限: [下拉选择: read-only/workspace-write/完全]  │

│    - 权限例外覆盖表 (session_permission_overrides):         │

│    - 私聊新建默认开关: [Switch 开/关, 默认开]                │

│    - Coding 工具例外表 (coding_tools_overrides):            │
│      [目标ID, 目标类型(私聊/群聊), 是否开启, 备注]           │
└─────────────────────────────────────────────────────────────┘
```

## 3. 详细逻辑规格

### 3.1 发言黑名单门控逻辑
- **拦截生效层**：位于 `src/index.ts` 顶层入站流程，在 `mediaManager` 媒体预下载与 `db.saveMessage(record)` 消息入库完成后立即执行；
- **命中判定**：
  - 私聊场景：若 `fromUser` 存在于 `private_blacklist` 中，触发拦截；
  - 群聊场景：若 `event.group_id` 存在于 `group_blacklist` 中，触发拦截；
- **执行动作**：
  - 输出一条日志：`[Plugin] 命中发言黑名单 (peer: ${peer})，消息已入库但阻断一切唤醒与指令`；
  - 立即 `return` 终止后续流转；
  - **管理员不豁免**：即使 `fromUser` 存在于 `admins` 管理员白名单中，黑名单依旧生效并终止（防止管理员在测试黑名单群/账号时被意外唤醒）；
  - **全面静默**：斜杠命令、等待门控、提问/审批回复、唤醒判定（`shouldWakeup`）、主动回复（`proactiveManager`）全部不触发。

### 3.2 新建会话权限模式装配逻辑
- **支持模式**（与 DSH `@deepseek-ai/dsh-permission-presets` 严格对齐）：
  - `'read-only'`：只读模式，禁止一切文件写入与系统执行；
  - `'workspace-write'`：工作区读写模式，限制在当前工作区路径内操作；
  - `'danger-full-access'`：完全模式，无沙箱路径限制。
- **配置项**：
  - `session_permission_private_default`: 默认 `'workspace-write'`；
  - `session_permission_group_default`: 默认 `'read-only'`；
  - `session_permission_overrides`: 例外列表。
- **生效规则**：
  - 当且仅当创建**新会话**时生效（`agents.create` 成功创建全新的 Session，或通过 `/新建` / `/clear` 重置会话时）；
  - 判定流程：
    1. 解析当前 `peer` 的目标主体与类型；
    2. 优先匹配 `session_permission_overrides` 中是否有对应的 `id` 与 `type`；
    3. 若匹配成功，使用其指定的 `permission`；
    4. 若未匹配，按私聊/群聊取对应的默认值；
    5. 调用 `permissionPresets.set(session, targetPreset)` 将权限预设写入会话上下文。
  - 会话热恢复（`agents.resume`）保持已有权限状态不变。

### 3.3 Coding 工具组装载与硬隔离逻辑
- **受控 Coding 工具清单**（共 7 个）：
  - 文件类：`read`, `write`, `edit`, `read_image`, `working_directory`
  - 终端类：`bash`, `pwsh`
  - 其余 QQ 专属工具、表情包工具、记忆工具、黑话工具、定时任务工具及官方 Web 搜索不受影响。
- **配置项**：
  - `coding_tools_private_default`: `boolean`，默认 `true`；
  - `coding_tools_group_default`: `boolean`，默认 `false`；
  - `coding_tools_overrides`: 例外列表。
- **生效规则**：
  - 在 `SessionAgentRunner.getOrCreateAgent` 内部的 `setupFn(agentCtx)` 中执行；
  - 判定流程：
    1. 优先查 `coding_tools_overrides` 中是否有该目标对象的例外配置；
    2. 若未匹配，按私聊/群聊读取对应的默认开关；
    3. 若判定结果为**关闭（false）**：
       ```ts
       if (typeof agentCtx?.tools?.restrict === 'function') {
         agentCtx.tools.restrict({
           deny: ['bash', 'pwsh', 'read', 'write', 'edit', 'read_image', 'working_directory'],
         });
       }
       ```
    4. 被 deny 的工具不会暴露给 LLM，既防越狱又节省 Token 开销。

## 4. 配置 Schema 与类型定义（`src/types/` & `src/config/schema.ts`）

### 4.1 实体结构定义
```ts
export type DshPermissionPreset = 'read-only' | 'workspace-write' | 'danger-full-access';

export interface BlacklistItem {
  id: string;
  remark?: string;
}

export interface SessionPermissionOverride {
  id: string;
  type: 'user' | 'group';
  permission: DshPermissionPreset;
  remark?: string;
}

export interface CodingToolsOverride {
  id: string;
  type: 'user' | 'group';
  enabled: boolean;
  remark?: string;
}
```

### 4.2 BridgePluginConfig 新增字段
所有字段均配置 `.volatile()` 保证 DSH 0.2.1 运行时热更新一致性：
- `private_blacklist`: `BlacklistItem[]`（默认 `[]`）
- `group_blacklist`: `BlacklistItem[]`（默认 `[]`）
- `session_permission_private_default`: `DshPermissionPreset`（默认 `'workspace-write'`）
- `session_permission_group_default`: `DshPermissionPreset`（默认 `'read-only'`）
- `session_permission_overrides`: `SessionPermissionOverride[]`（默认 `[]`）
- `coding_tools_private_default`: `boolean`（默认 `true`）
- `coding_tools_group_default`: `boolean`（默认 `false`）
- `coding_tools_overrides`: `CodingToolsOverride[]`（默认 `[]`）

三方对齐保证：`schema.ts`、`server/routes.ts`、`client/card.tsx` 保持 100% 恒等。

## 5. Web UI 设置卡片落地（`src/client/`）

1. **Tab 注册**：`SETTINGS_TABS` 增加 `{ id: 'security', label: '权限与安全' }`；
2. **样式风格**：遵循官方 DSH 规范（CSS 变量 `var(--dsw-alias-*)`，官方 Input/Switch/Select 语义）；
3. **交互能力**：
   - 黑名单：列表展示、输入 QQ/群号与备注快速添加、单项删除；
   - 会话权限：私聊/群聊默认下拉单选、例外表增删改查；
   - Coding 工具：私聊/群聊默认 Switch 开关、例外表增删改查。
