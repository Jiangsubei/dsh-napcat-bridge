## 1. 现状剖析与问题识别

### 1.1 现状：全量继承 DSH 默认 Coding 预设
在本次重构前，QQ 会话的 Agent 启动与装配逻辑位于 `src/gateway/session/agent-runner.ts`：
1. **预设挂载无差别**：在 `setupFn` 中调用 `presets.mount(agentCtx)` 时未传递 `id` 参数，因此默认挂载了 DSH 的内置预设（`standard` 编码预设）；
2. **提示词冗余膨胀**：DSH 默认的 System Prompt 包含全套针对软件工程编码（"You are a coding agent..."、Git 工作流、Shell 语法规则等），消耗大量不必要的 Context 预算；
3. **工具无隔离暴露**：
   - DSH 编码工具（`bash`, `pwsh`, `read_file`, `write_file`, `edit_file`, `fs_search`, `jobs`, `subagent` 等）全量对 QQ 暴露；
   - QQ 桥接工具（`read_chat_history`, `send_file`, `poke_user`, `wait_for_user_messages`, `react_message`, `list_group_files` 等）最初在根上下文全局 `ctx.tools` 注册；
   - 之前缺乏针对 QQ 会话的专用预设隔离，必须在 `src/index.ts` 中通过 `system-prompt/assemble` 过滤器和 `toolsSvc.guard` 防御性拦截胶水代码来防止非 QQ 会话调用 QQ 工具。

## 2. DSH 底层能力确切事实考证

基于对本地 `node_modules/@deepseek-ai/*` 的源码与类型定义查验，确认以下底层事实：

### 2.1 `@deepseek-ai/dsh-agent-presets` 机制
- **存储路径**：内置预设位于包内 `presets/{standard,minimal,ptc,cordis}`；用户自定义预设位于 `<dshHome>/.agent-presets/<preset-name>/`。
- **文件组成**：
  - `preset.yml`：名称 (`name`)、描述 (`description`)、顺序 (`order`)；
  - `agent.cordis.yml`：声明式加载的 Cordis 子插件列表。
- **运行特征**：
  - **进程级 Standing Mount**：预设是单例常驻挂载的（`mounted ONCE per preset under a standing scope`），不同 Agent 通过 scope 绑定加入；
  - **跨插件子插件导出**：可通过在 `package.json` 中配置 exports（如 `"./tools": "./dist/tools/plugin.js"`），将桥接工具打包为独立 Cordis 插件供预设声明加载。

### 2.2 `@deepseek-ai/dsh-system-prompt` 机制
- **完全覆盖选项 (`complete: true`)**：
  ```ts
  agentCtx.systemPrompt.section({
    name: 'qq:complete_system_prompt',
    order: 0,
    text: effectivePromptText,
    complete: true, // 关键：直接将该 section 作为完整 System Prompt，屏蔽全局所有冗余 Coding 提示词
  });
  ```
- **Persona 替换插槽**：
  - 支持 `PERSONA_PREFIX_SECTION` ("deployment:persona-prefix") 与 `PERSONA_SUFFIX_SECTION`，在 Agent 作用域内注册同名 section 即可直接局部覆盖全局 Persona。

### 2.3 `@deepseek-ai/dsh-tools` 机制
- **精准工具限制 (`tools.restrict`)**：
  ```ts
  agentCtx.tools.restrict({
    allow: ['read_chat_history', 'send_file', 'poke_user', 'read_memory'],
    // 或 deny: ['tool_bash', 'tool_pwsh']
  });
  ```
  - 原生支持按 Agent 作用域（`agentCtx`）进行全局工具的白名单（`allow`）或黑名单（`deny`）裁剪；
  - 被 restricted 掉的工具不会出现在发给 LLM 的 tools 列表中，既省 token 又硬隔离。

## 3. 架构设计方案选型

针对建立 QQ 会话专属预设（控制每一个工具、纯化 System Prompt），进行了以下方案权衡：

### 方案 A：轻量受控预设系统（Session Profile System）
- **核心思路**：在 `.dsh/napcat/presets/` 目录下放置 JSON/YAML 配置文件，由 `agent-runner.ts` 动态读取并执行 `systemPrompt.section({ complete: true })` 与 `tools.restrict`。

### 方案 B：分层自治模式（Prompt 软演进 + 权限硬策略）
- **核心思路**：将“人设与行为准则（Soft Soul）”与“系统工具与权限（Hard Policy）”解耦，工具权限由系统预设模板保护，人设支持自演进。

### 方案 C：DSH 原生 Preset 挂载模式（最终采纳核心）
- **核心思路**：
  - 在 `cordis.patch.yml` 中声明原生预设 `preset-qq-session`（id 为 `qq-session`）；
  - 配置精简的 persona（`complete: true`，屏蔽 Coding 规则）；
  - 声明加载官方基础工具（文件操作、跨平台 Shell、Web 搜索等）与 NapCat 专属工具插件 `dsh-napcat-bridge/tools`；
  - 在 `agent-runner.ts` 的 `setupFn` 中通过 `presets.mount(agentCtx, 'qq-session')` 挂载；
  - 彻底注销并移除 `system-prompt/assemble` 与 `toolsSvc.guard` 防御胶水代码。
