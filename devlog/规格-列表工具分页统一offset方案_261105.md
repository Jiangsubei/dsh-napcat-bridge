# 列表工具分页统一 offset 方案

> 日期：2026-11-05
> 状态：已实施并通过契约测试
> 范围：`get_friend_list`、`get_group_list`、`get_group_member_info`、`list_faces`、`read_qzone_feeds`

## 1. 背景与决策

当前 Agent 工具中存在两套不一致的分页语义：

- `get_friend_list`、`get_group_list`、`get_group_member_info` 使用 `page + limit`；
- `read_qzone_feeds` 使用 `offset + limit`，并额外支持 `cursor` / `after_feed_id`；
- `list_faces` 只有 `limit`，内部将 offset 写死为 0。

其中前三个工具的数据来源都是“一次性拉取全量 → 本地缓存 → 过滤 → 切片”，`page` 只是派生抽象，模型需要自行计算 `(page - 1) * limit`，一旦中途改变 `limit`，页号含义就会漂移。因此统一改为 `offset + limit`。

### 已确认决策

1. 三个列表工具**硬切 offset，不保留 page 别名**。
2. 好友 / 群 / 群成员在切片前做**确定性排序**，保证序号长期稳定。
3. QQ 空间**不新增 page**；好友动态流以 `cursor` 为优先翻页方式，`offset` 保留。
4. `list_faces` 补齐 `offset`，纳入统一的 `offset + limit` 规范。

## 2. 统一 offset + limit 契约

### 2.1 入参

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `offset` | number | `0` | 从 0 开始的起始序号偏移，`0` 表示从第 1 条开始；小于 0 或非法值按 0 处理 |
| `limit` | number | 见各工具 | 单次返回条数，超出上限时收敛到上限 |

`offset` 作用于**过滤后的结果集**（`query` / `role` / `mood` / `tag` 等筛选之后），不是原始全量数组。

### 2.2 返回字段

所有纳入本规范的列表工具统一返回：

| 字段 | 类型 | 说明 |
|---|---|---|
| `total` | number | 本次实际返回条数 |
| `total_matched` | number | 过滤后匹配的总条数 |
| `offset` | number | 本次生效的起始偏移（归一化后） |
| `limit` | number | 本次生效的条数上限（归一化后） |
| `has_more` | boolean | 是否还有更后面的数据 |
| `next_offset` | number? | 仅当 `has_more = true` 时返回，等于 `offset + total`，可直接回填下一次调用 |
| `message` | string? | 面向 Agent 的翻页引导语 |

移除 `page` 与 `total_pages`。

### 2.3 面向 Agent 的序号展示

`render` 输出必须使用**跨页连续的 1-based 全局序号**，例如 `offset = 20` 时第一条显示为 `21.`，而不是重新从 `1.` 开始。这样模型看到“第 21 条”即可直接推断下一次 `offset: 20` 或直接使用返回的 `next_offset`。

引导语示例：

- 还有更多：`本次展示序号 21~40（共 58 人）。继续浏览请传入 offset: 40。`
- 已是末尾：`已展示至最后一页（序号 41~58，共 58 人）。`
- offset 越界：`offset 60 超出范围（共 58 人），请使用 0~57 之间的偏移量。`

## 3. 确定性排序规则

| 工具 | 排序键 | 方向 |
|---|---|---|
| `get_friend_list` | `user_id` 数值 | 升序 |
| `get_group_list` | `group_id` 数值 | 升序 |
| `get_group_member_info` | `user_id` 数值 | 升序 |
| `list_faces` | `added_at`，同值再按 `id`（沿用现有 SQL） | 降序 |

排序在过滤之后、切片之前执行。缓存刷新不会改变同一批数据的相对顺序，因此序号在同一数据快照内稳定。

## 4. QQ 空间例外契约

`read_qzone_feeds` 保持 `offset + limit`，不新增 `page`：

- `scope = friends`：优先使用 `cursor` / `next_cursor` 连续翻页；显式传入 `cursor` 时忽略 `offset`，保持游标单步幂等。
- `scope = self / user`：底层 `get_qzone_msg_list` 使用 `num + pos`，`pos` 即数值偏移，`offset` 直接映射。
- `after_feed_id` 保留为断点续读能力。
- 工具描述中明确“好友动态流请优先传 cursor”，并将 `offset` 标注为未传 cursor 时的兼容路径。

## 5. 各工具默认值与上限

| 工具 | 默认 limit | 上限 |
|---|---|---|
| `get_friend_list` | 20 | 50 |
| `get_group_list` | 20 | 50 |
| `get_group_member_info` | 20 | 50 |
| `list_faces` | 100 | 100 |

## 6. 验收标准

1. 四个列表工具的参数定义中只存在 `offset` / `limit`，不存在 `page` / `total_pages`。
2. 契约测试覆盖：默认值、翻页、末页、越界、`limit` 收敛、`next_offset` 计算、连续全局序号渲染、确定性排序。
3. 契约测试覆盖：好友 / 群 / 群成员按 ID 升序，不受入参原始顺序影响。
4. `read_qzone_feeds` 显式 `cursor` 时 `offset` 不参与切片；`next_cursor` 行为不回归。
5. 所有结果通过 DSH Lossless JSON 校验（无 `undefined` 字段）。
6. `pnpm typecheck`、相关 `pnpm test:quick` 全绿，交付前执行 `pnpm build`。
